# x-operator

通用型 X（推特）运营半自动化工具：定时发推、监控推主回复、语义搜索回复、LLM 素材匹配与撰写、多语言+自动翻译、人工审核队列。

- 完整规格：[docs/design.md](docs/design.md)（v1.0）
- 旧版窄范围草稿（已被取代，仅存档）：docs/archive/twitter-autopost-spec-v0.1.md

---

## 快速开始

Windows 双击 `start.bat`（需先装 `uv`），或命令行：

```bash
uv sync
uv run python -m x_operator.main
```

浏览器打开 http://localhost:8080。首次启动会自动建库并写入一批演示数据
（一个 Mock 账号、几条中日英回复素材、一个监控推主、一条搜索规则）。旧版本的数据库会自动升级，数据不丢。

## 两种运行模式

| | Mock 演示模式（默认） | 真实模式 |
|---|---|---|
| 抓取/发送 | 走假适配器，每次「运行」都会冒出几条样本推文，零凭据零风险 | 用账号里填的凭据真的去 X 抓取和发送 |
| 切换 | 设置 → 运行模式 → 关掉「Mock 演示模式」 | |
| 前提 | 无 | 至少一个账号填好凭据且「测试连接」成功 |

演示模式下添加的监控推主是假的（卡片上有「演示数据」标记），切到真实模式后会被自动跳过，删掉重新添加即可。
设置 → 数据 里有「清除演示数据」一键清理演示期间的抓取记录/队列。

## 账号与凭据（设置 → 账号 → 编辑 / 填凭据）

- **官方 API 通道**（主号必须用它）：在 developer.x.com 建 App，权限设为 *Read and Write*，
  填 API Key / API Key Secret / Access Token / Access Token Secret（Bearer Token 选填）。
  按量计费：读约 $0.005/条、发 $0.015/条、含链接推文 $0.20/条。
- **非官方 Cookie 通道**（仅小号）：浏览器登录小号 → F12 → 存储/Application → Cookies → x.com，
  复制 `auth_token` 与 `ct0` 填入。也可填用户名/密码（+2FA 的 TOTP 密钥）让程序登录，成功后自动保存 Cookie。
  可选代理。风控风险高于官方通道，务必保守限速。
- 凭据存在本机 `data/x_operator.db`，不会上传；`data/` 已在 .gitignore。
- 「测试连接」不需要关演示模式，会直接用填的凭据连一次 X 并告诉你凭据对应的是哪个账号。
- 账号卡片还可设日发帖/回复上限、发送随机间隔、活跃时段与时区——分发器只在活跃时段内、间隔到了才发。

## 一条推文的旅程

```
监控推主 / 搜索规则 → 抓取记录（每条推文：打分、理由、状态）
   → 匹配素材 → 审核队列（待审核）→ 人工批准（可改文案）→ 待发送
   → 分发器（活跃时段 / 间隔 / 日上限 / 冷却 / 黑名单 / 去重账本）→ 已发送
```

各页面：

- **仪表盘**：概况 + 「就绪检查」（没账号/没凭据/没素材会直接标红告诉你）+ 手动运行按钮。
- **审核队列**：逐条看 AI 理由、改文案、批准/跳过/拉黑；每条可删除，也可按状态一键清空；待发送可撤回。
  自动刷新只在条目集合变化时重绘，不会冲掉正在编辑的文案。
- **抓取记录**：监控/搜索抓到的所有推文，含未达标/未匹配的，说明为什么没进队列；可「重新匹配」、删除、拉黑作者、批量清理。
- **素材库**：增删改、启用/归档；删除进**回收站**，可恢复或彻底删除、清空回收站。回收站里的素材不参与匹配。
- **监控推主**：添加（真实模式会去 X 解析用户）、编辑备注/含回复、启停、重置游标、删除。
- **搜索规则**：关键词 + 语义条件 + 达标分，启停、试运行（只打分不入库）、重置游标、删除。
- **定时计划**：新建/编辑/暂停/恢复/删除，「立即生成一次」不等到点。
- **设置**：账号、运行模式、LLM 网关、合规参数、预算、黑名单、数据清理。

运行按钮的结果会弹出中文说明，例如「没有启用的监控推主」「不在活跃时段（09:00-22:00 Asia/Tokyo），3 条待发到时段内自动发送」，
不会再出现「点了没反应」。

## LLM

设置 → LLM 填 OpenAI 兼容网关（如 apimax）的 base_url + api_key 后，相关性打分和素材匹配走真实 LLM；
不填则用内置关键词启发式兜底，离线也能演示。

## 目录结构

```
x_operator/
  db/         schema.py(DDL v2) database.py(连接/自动迁移) seed.py(默认设置+演示数据)
  adapters/   base.py(异常/数据类/抽象基类) mock.py(Mock) real.py(tweepy 官方 + twifork 非官方) factory.py
  llm/        prompts.py client.py(网关调用+启发式兜底)
  core/       compliance.py matcher.py monitor.py search.py dispatcher.py scheduler.py schedule_calc.py
  ui/         layout.py + 8 个页面(dashboard/queue/targets/materials/watched/rules/schedule/settings)
  config.py   main.py
config/settings.toml   start.bat / start.sh
```
