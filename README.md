# x-operator

通用型 X（推特）运营半自动化工具：定时发推、监控推主回复、语义搜索回复、LLM 素材匹配与撰写、多语言+自动翻译、人工审核队列。

- 完整规格：[docs/design.md](docs/design.md)（v1.0）

---

## 快速开始

Windows 双击 `start.bat`（需先装 `uv`），或命令行：

```bash
uv sync
uv run python -m x_operator.main
```

浏览器打开 http://localhost:8080。首次启动只建空库，**没有任何演示/模拟数据**，也没有「演示模式」——
所有抓取和发送都用你在「设置 → 账号」里填的真实凭据直连 X。旧版本的数据库会自动升级并清掉之前的演示数据（你自己加的账号/素材/规则会保留）。

> **安全提醒**：页面没有登录保护，设置页能看到所有账号的密码 / Cookie / 密钥，所以程序**默认只监听本机**
> （`config/settings.toml` 里 `host = "127.0.0.1"`）。不要改成 `0.0.0.0` 放到局域网/公网上。

起步三件事：① 设置 → 账号 添加账号并「测试连接」；② 素材库 加几条「回复」素材；③ 监控推主 / 搜索规则 加来源，然后点「运行一次」。
仪表盘的「就绪检查」会直接告诉你还差哪一步。

## 账号与凭据（设置 → 账号 → 添加 / 编辑）

弹窗里有可展开的**手把手图文步骤**（F12 在哪、点哪个标签、复制哪一列），这里只列要点：

- **官方 API 通道**（主号必须用它）：developer.x.com → App → Settings 里把权限改成 *Read and write* →
  Keys and tokens 生成 API Key / API Key Secret / Access Token / Access Token Secret（Bearer 选填）。
  按量计费：读约 $0.005/条、发 $0.015/条、含链接推文 $0.20/条。
- **非官方通道**（仅小号），两种方式填一种即可：
  - 方式一 **Cookie**：Chrome/Edge 登录小号 → F12 → Application（应用）→ Cookies → https://x.com →
    复制 `auth_token`（40 位）和 `ct0`（32 或 160 位）的 **Value** 值。保存时会做格式体检，复制错列会直接提示。
  - 方式二 **用户名 + 密码 + 两步验证 TOTP 密钥**：程序自己走登录流程（自研，不用 twikit 自带的、会卡在
    键盘输入上的那套），登录成功后自动把 Cookie 存回账号；Cookie 失效时自动重新登录。
    支持：密码、TOTP 两步验证、X 要求补邮箱确认身份（填了「邮箱」就自动过）。
    **不支持邮箱验证码**——遇到会弹出明确提示，先在浏览器登录一次完成验证再试，或改用方式一。
- **代理**：留空自动使用系统当前代理（Windows 设置里的代理 / HTTP(S)_PROXY 环境变量），填 `direct` 强制直连，
  也可填 `http://127.0.0.1:7890` 指定。「测试连接」成功时会告诉你走的是哪个代理。
- 凭据存在本机 `data/x_operator.db`，不会上传；`data/` 已在 .gitignore。
  **所有数据（账号、LLM key、规则、素材、模板、抓取记录）都在这一个文件里**，浏览器只是显示窗口——换 IP、换浏览器打开都是同一份；
  换电脑跑要把 `data/` 一起带走。备份 = 复制这个文件。
- 账号卡片还可设日发帖/回复上限、发送随机间隔、活跃时段与时区——分发器只在活跃时段内、间隔到了才发。

## 一条推文的旅程

```
监控推主 / 搜索规则 → 抓取记录（每条推文：打分、为什么被过滤、状态）
   → 匹配素材 → 审核队列（待审核）→ 人工批准（可改文案）→ 待发送
   → 分发器（活跃时段 / 间隔 / 日上限 / 冷却 / 黑名单 / 去重账本）→ 已发送
```

各页面：

- **仪表盘**：概况 + 「就绪检查」（没账号/没凭据/没素材会直接标红告诉你）+ 手动运行按钮。
- **审核队列**：逐条看生成说明、改文案、**换素材**、批准/跳过/拉黑；每条标明来源（AI 匹配素材 / 手动选素材 / AI 撰写 / 定时）；
  已发送条目给出 X 上的链接，并**自动回查是否真的存在**（发送接口返回成功 ≠ 一定发出去了；查不到会标红），可手动「重新回查」。
  你正在改文案或开着弹窗时，自动刷新不会把页面冲掉。
- **抓取记录**：监控/搜索抓到的所有推文。被过滤的每条都写明**为什么没进队列**，页顶有各状态说明；可按来源、规则、状态筛选，
  支持 URL 直达（`/targets?source=search&rule=3`）。每条可 **「选素材」**（手动从素材库挑一条、可改文案）、
  **「AI 撰写」**（按创作要求现写；写好的创作要求可**存为模板**，下次同类场景直接从模板选——规则/推主里的
  「AI 创作要求」也能用同一批模板）、「自动匹配」、删除、拉黑作者。
- **素材库**：增删改、启用/归档、回收站；**「AI 生成素材」**：给主题、风格、语言、场景、必须包含的 @/链接和条数，
  预览勾选后入库（标记 AI）。
- **监控推主**：添加后可编辑：**首次回溯小时数**、含不含回复、**回复方式**、AI 创作要求。
- **搜索规则**：关键词（**逗号隔开 = 命中任意一个**，也可直接写 X 语法）+ 语义条件 + 达标分 + **语言多选** +
  **首次回溯小时数** + **观看量门槛** + **回复方式**；观看量门槛在**抓取端**生效——改按 X 的「热门」排序
  （小号通道 Top / 官方 API relevancy，刚发的推文观看量都低，按时间倒序凑不到）在时间窗内找，一页不够就继续翻页，直到凑够
  「每次抓取条数」或扫到上限（条数 × 10，最多 500，且不超过当日剩余读额度），低于门槛的当场丢掉不入库，
  不会出现"抓 15 条全被过滤"的情况（官方 API 按扫描条数计费，运行结果里会写扫了多少、丢了多少、最高观看量是多少）；**「AI 生成规则」**：用大白话描述想找谁，AI 给出关键词、语义条件、语言，检查后保存。
  每个参数旁边都有说明和推荐值。右上「运行所有规则」跑所有启用的规则；每张卡片上「运行此规则」只跑这一条（停用的也能跑）——
  两者都是正式运行：结果进抓取记录、推进游标（没有只看不存的试运行）。运行时弹进度框，实时显示到第几条规则、在抓取/打分/生成哪一步。

### 回复怎么生成（每条规则 / 每个推主单独选）

| 回复方式 | 做什么 | 需要 |
|---|---|---|
| 匹配素材库（默认） | 从启用中的「回复」素材里挑一条（优先同语言），**原文使用**（可开「允许轻微润色」）。**宽进**：只要有素材就一定给一条草稿——AI 择优，AI 拒绝/出错/拿不准时按规则挑用得最少的一条并在理由里说明 | 素材 |
| AI 按要求创作 | 按你写的「创作要求」（主题、立场、必须带的 @/链接、语气）每条现写，必带项缺了会自动重写 | LLM + 创作要求 |
| 只抓取，手动处理 | 不自动生成，你在抓取记录里逐条「选素材」或「AI 撰写」 | — |

无论哪种，都只生成**待审核**草稿，最后由你批准才发。

### 多账号：谁来回、谁来发

- **主号**：账号弹窗里的「设为主号」开关（只有官方 API 通道能当主号）。主号用来发自己的帖子、以及抓取通道切到「官方 API」时负责读取；默认**不参与回复**。
- **回复账号**：每条搜索规则 / 每个监控推主可选——
  - 「自动轮流」（默认）：在启用中的小号里挑最闲的（按今天已回 + 队列里待审核/待发送的条数，跳过已到日上限的），
    一轮抓到的多条草稿会均匀分到各小号；一个小号都没有时才退回主号。
  - 指定某个账号：固定用它。
  - 审核队列里每条待审核条目都能临时改「发送账号」。
- **发帖账号**：定时计划新建时选。
- 去重账本按推文去重：同一条推文只会被一个账号回。

### 时间窗

不再有全局的「推文最大年龄」。每条搜索规则、每个监控推主各有一个**首次回溯（小时，默认 24）**：
第一次运行（或重置游标后）只抓这个时间窗内的；之后每次只抓上次游标之后的新内容。
官方 API 的搜索最多只能查最近 7 天（168 小时），填得再大也按 168 抓；监控推主每次最多拉 100 条，更早的下一轮凭游标继续。
- **定时计划**：新建/编辑/暂停/恢复/删除，「立即生成一次」不等到点。程序没开着错过了到点：错过不到「宽限小时数」照常补发，超过就标「错过」（周期计划跳到下一次）。
- **设置**：账号、自动运行、LLM 网关、合规参数、预算、黑名单（@handle 或数字 id 都能拦）、数据清理。数字参数保存时会校验范围。
  - **自动运行**页列出所有会自己跑的功能：自动搜索、自动监控（受总开关 + 各自的单独开关，节奏可选**每隔 N 分钟**或
    **每天固定时间点**如 `08:00, 20:00`，按所选时区；改完立即生效）、发送分发（每分钟，可单独关掉只手动发）、
    定时计划检查 + 过期清扫（每分钟，始终开）。总开关默认关；表格里显示每项的状态和下次运行时间。

### 发送保护（防重复、防误停）

- 推文发到 X 之后，程序先把「已发出 + X 的推文 id」写死再做其他记账；程序中断时正在发送、结果未知的条目，重启后标为「失败，请到 X 上确认」，**不会自动重发**。
- 发送请求超时/断网时，先到自己的时间线上找一下刚才那条（回复看是不是回的同一条推文），找到就按已发出处理。
- 同一账号只允许一个发送在进行（手动「触发发送」和后台每分钟的自动分发不会撞车）。
- X 限流（429）不算重试次数，账号暂停到 X 给的重置时间后自动继续。
- 非官方通道解析不了 X 的返回时，先探一下登录态：Cookie 好好的就不会被当成「凭据失效」清掉。

### 读额度（设置 → 预算）与费用

- **只有官方 API 通道花钱**（X 按返回的推文条数计费，被过滤掉的也算；发一条也计费，含链接的贵得多）。小号 Cookie/密码通道 X 不计费。
- **抓取通道**（设置 → 预算）：默认**走小号**——用启用中的非官方账号去读，免费，读额度限制不生效；多个小号时轮流用今天读得最少的那个分摊风控。
  切到「官方 API」才用主号/官方号去读、按条计费、读额度生效。所选通道没有账号时自动退回另一个通道，运行结果里会写明这次用的是谁。
- 程序怎么数：每次抓取按返回条数记进 `action_log.reads_consumed`（开了观看量门槛按扫描条数），发送后回查记 1 条。读额度只统计官方通道；仪表盘另行显示小号通道的读取量。
- 真的会拦：自动轮询在「剩余 ≤ 熔断保留」时停跑，手动运行在当日额度用完时拒绝，每天 0 点（UTC）重置；填 0 = 不限。
- 仪表盘按 $0.005/条估算本月官方读费用——这是程序自己的估算，不是 X 账单，实际单价以开发者后台为准。

## 过滤策略：默认保留

关键词已经命中的推文，原则上都留给人工审核，只剔除明显没用的。一条推文按顺序过五关（搜索规则页顶部有同样的说明，
并显示当前生效的数值），任何一关没过都会写进「抓取记录」并注明原因：

1. **时间窗**：首次运行只看规则/推主「首次回溯」小时数内的；之后只抓上次游标之后的
2. **语言**在规则勾选范围内（留空不限；语言不明放行）
3. **预检**：转推 / 自己的推 / 黑名单 / 已回复过 / 作者冷却期内（默认 7 天）。前三关和已抓过的推文都不花 LLM
4. **相关性打分 ≥ 达标分**（默认 5）。有 LLM：本人明确符合 8~10、沾边拿不准 6~7、新闻/教程/招聘/广告 3~5、无关或看不出意思 0~2。
   无 LLM：有完整上下文 7、命中新闻/招聘/广告词 3、去掉链接/@/#/表情后不足 12 字 2。
5. **生成回复**（按规则的回复方式，见上表）；没生成的标为「达标但未生成回复」，可手动处理

旧库升级时，还停在旧默认值上的达标分（6/7）会自动放宽到 5、素材匹配置信度门槛 0.7 放宽到 0.4；你自己改过的值不动。

## LLM

设置 → LLM 填任意 OpenAI 兼容端点（官方或中转站）的 base_url + api_key 后，相关性打分按你写的语义条件来、素材匹配做语义择优；
不填则用上面说的关键词粗打分，能用但分不出"沾边"和"明确符合"。

### 哪些任务用轻量模型、哪些用强模型

| 任务 | 模型档 | 为什么 |
|---|---|---|
| 设置页「测试连接」 | 轻量 | 只是通不通 |
| 搜索规则：给每条推文打相关性分 | 轻量 | 量大、判断简单，省钱 |
| 匹配素材库（择优 / 润色） | 强 | 要做取舍，开了润色还要改写 |
| AI 按要求创作回复 | 强 | 要写东西 |
| AI 生成搜索规则 | 强 | 要理解意图、组织关键词 |
| AI 生成素材 | 强 | 要写东西 |

这张表的唯一来源是代码 `x_operator/llm/client.py` 里的 `SCENE_TIERS`：所有 LLM 调用都按它取模型，**没登记的场景直接报错**，
所以以后加新的 LLM 功能必须先在那里补一行——表不会过期。设置 → LLM 页会把它连同当前填的模型名一起显示出来。

## 目录结构

```
x_operator/
  db/         schema.py(DDL v8) database.py(连接/自动迁移) seed.py(默认设置 + 旧演示数据清理)
  adapters/   base.py(异常/数据类/抽象基类) real.py(tweepy 官方 + twifork 非官方 + 自研登录 + 系统代理) factory.py mock.py(仅测试)
  llm/        prompts.py client.py(网关调用+启发式兜底)
  core/       compliance.py matcher.py monitor.py search.py dispatcher.py scheduler.py schedule_calc.py budget.py accounts.py(回复账号轮流)
  ui/         layout.py pickers.py(共用弹窗/回复方式字段) + 8 个页面(dashboard/queue/targets/materials/watched/rules/schedule/settings)
  config.py   main.py
scripts/      smoke_test.py serve_check.sh
config/settings.toml   start.bat / start.sh
```
