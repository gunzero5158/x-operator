# x-operator

运行在本机的 X（Twitter）运营工具：从发现目标推文、筛选、生成回复，到审核和定时发布，在一个 Web 界面里完成。

支持多账号、多语言、素材匹配和 AI 创作。默认先生成草稿，由你审核；也可针对规则、监控推主或定时计划开启自动批准。

## 近期更新

- **两类记录支持批量自动匹配**：在「抓取记录」筛选「已过滤/未达标」或「达标但未生成回复」，勾选记录或全选当前列表，一次重新生成回复草稿。
- **任务进度不再挡住页面**：搜索、监控、批量匹配和 AI 生成使用右下角任务面板，可收起；等待期间可以继续操作、切换页面，结束后查看结果或错误详情。
- **AI 结果可以稍后处理**：生成素材和搜索规则后，从任务面板打开结果，检查、修改，再入库或保存。
- **雾灰 · 靛紫界面**：统一导航、按钮、表格和弹窗；白色卡片配清晰边框，标题区、正文区和操作区分层，密集信息更易读。
- **Cookie 搜索查询调整**：不再自动附加 `lang:` 条件，先抓取再按所选语言本地过滤，减少复杂查询返回空结果的情况；规则卡片显示实际查询，方便对照排查。

## 能做什么

| 环节 | 功能 |
|---|---|
| 发现内容 | 监控指定推主、关键词搜索、账号推荐流（For You）和关注流 |
| 筛选目标 | 语义相关性、语言（区分简体/繁体中文）、观看量区间、首次回溯时间窗；记录过滤原因 |
| 生成回复 | 匹配素材库、AI 按要求创作，或只抓取后手动处理；支持创作要求模板 |
| 批量补处理 | 对未达标或未生成回复的记录重新自动匹配，汇总入队、未匹配、跳过和错误数量 |
| 审核与发布 | 修改文案、换素材、批准或跳过；按账号筛选、批量转移未发送任务，回查发送结果 |
| 定时发帖 | 固定素材、素材池轮流、AI 按主题创作；支持周期计划、改写变体和附件素材池 |
| 多账号管理 | 官方 API、Cookie 或密码登录；抓取账号轮换、指定/排除回复账号、独立时区与活跃时段 |
| 发送控制 | 黑名单、作者冷却、去重、长度检查、日上限、发送间隔及官方 API 读额度控制 |

通常的工作流程：

```text
监控推主 / 搜索规则
        ↓
抓取记录 → 查看打分、过滤原因 → 单条或批量自动匹配
        ↓
任务队列 · 待审核 → 修改 / 批准 → 待发送 → 分发器 → 回查发送结果

定时发帖计划 → 到点生成草稿 → 任务队列
```

开启自动批准后，符合条件的自动生成内容可直接进入待发送；从抓取记录手动或批量重新匹配的草稿仍进入待审核。

## 快速开始

需要 Git 和 [uv](https://docs.astral.sh/uv/)，项目要求 Python 3.11 及以上。

```bash
git clone https://github.com/gunzero5158/x-operator.git
cd x-operator
uv sync --locked
uv run python -m x_operator.main
```

也可以在下载项目后，Windows 双击 `start.bat`；Linux / macOS 在项目目录运行 `bash start.sh`。

启动后打开 [本地页面](http://127.0.0.1:8080)，按仪表盘的「就绪检查」配置：

1. **设置 → 账号**：添加账号并测试连接。官方 API 填应用密钥；非官方通道可填 `auth_token`、`ct0`，或配置密码登录。页面提供填写说明。
2. **设置 → LLM**：填写 OpenAI 兼容网关的 `base_url`、`api_key` 和模型名。轻量模型负责相关性打分，强模型负责素材匹配与创作。
3. **素材库 / 创作要求**：使用素材匹配时，先添加回复素材；使用「AI 按要求创作」时，在规则或监控推主中填写要求。
4. **监控推主 / 搜索规则**：添加来源、筛选条件和回复方式，手动运行后到「抓取记录」查看结果。
5. **任务队列**：检查生成的草稿并批准，由分发器按账号活跃时段、间隔和上限发送。
6. 需要自动抓取时，到 **设置 → 自动运行** 开启搜索、监控并设置节奏；自己发主贴使用 **定时发帖**。

不配置 LLM 时，筛选和素材匹配会使用规则兜底，AI 创作不可用。发送分发与定时计划有各自的运行设置，详见[使用指南](docs/guide.md)。

### LLM 网关与超时

可使用你已有的 OpenAI 兼容服务，也可通过 [apimax](https://apimax.io) 获取 API。设置页提供「填入推荐配置」快捷按钮，模型名须以实际网关支持的名称为准。

「返回超时」默认 60 秒，可在 10–600 秒间调整；生成多条素材按此值的两倍等待。任务面板显示耗时和结果，超时信息包含任务、模型及等待时间。模型返回了文本或产生了费用，并不等于草稿已经成功入队。

## 批量处理与任务进度

### 重新处理未生成回复的记录

1. 打开 **抓取记录**，选择「达标但未生成回复」或「已过滤/未达标」。可以再按来源、搜索规则缩小范围。
2. 勾选记录，或点 **全选当前列表**，然后点 **批量自动匹配**。
3. 在右下角查看进度和处理汇总，完成后点 **查看待审核**。

全选只包含当前显示的记录（最多 150 条），不会自动选中数据库里所有记录。匹配使用各条记录的来源规则：素材匹配或 AI 创作；「只抓取，手动处理」模式下，手动自动匹配会尝试从素材库挑选。

与单条自动匹配一样，批量处理跳过抓取阶段的打分和预检；**生成草稿不代表可以直接发送**，发送阶段仍检查黑名单、冷却、去重等条件。已删除、状态已变化或正在自动匹配的记录会跳过；一条失败不阻断剩余记录。

### 等待期间继续操作

右下角任务面板可以收起，切换页面或刷新页面后仍可查看同一服务进程中的任务。搜索、监控和批量处理显示实际阶段或完成数量；AI 生成没有可靠百分比时显示等待动画和耗时。

素材和搜索规则的 AI 结果通过 **查看生成结果** 打开，确认后才保存。任务面板及尚未保存的生成结果保存在内存中，**服务重启后不会保留**；已经入库的素材、抓取记录和队列草稿不受影响。

## 常见问题

**模型有返回，为什么待发送里没有新内容？**

先看任务面板的处理结果，再检查「待审核」，最后查看抓取记录的「达标但未生成回复」及具体原因。还可能是未找到合适素材、未配置创作要求、账号不可用，或模型返回格式不符合要求。定时发帖的失败原因也会显示在计划卡片上。

**X 网页搜索有结果，工具却抓不到？**

对照规则卡片里的实际查询，并检查账号、首次回溯时间、游标、语言和观看量门槛。Cookie 通道只是不自动拼接语言条件，抓取后仍会按所选语言过滤。搜索结果、游标和观看量筛选的详细行为见[使用指南](docs/guide.md)。

**怎样备份或换电脑？**

停止服务后备份整个 `data/` 目录（数据库和附件），以及自己修改过的 `config/settings.toml`。新电脑安装依赖后放回对应目录即可继续使用。不要只复制代码而遗漏数据，也不要将含凭据的数据目录提交到 GitHub。

## 本地开发与更新

项目使用 Python、NiceGUI、SQLite 和 APScheduler。页面在 `x_operator/ui/`，任务逻辑在 `x_operator/core/`，X 接口在 `x_operator/adapters/`，LLM 调用在 `x_operator/llm/`。

统一界面样式在 `x_operator/ui/theme.css`，修改后刷新页面即可加载；修改 Python 代码后需要重启服务。

更新前停止服务并备份数据，先提交或妥善保存自己的改动，再运行：

```bash
git pull --ff-only
uv sync --locked
uv run python -m x_operator.main
```

如果本地与远端提交已分叉，`--ff-only` 会停止；先检查并合并自己的开发改动，不要用强制重置覆盖。

开发时可按需执行以下检查（不会替代真实账号和网关的实际验证）：

```bash
uv run python scripts/smoke_test.py   # 离线检查
bash scripts/serve_check.sh          # 本地服务页面检查
```

## 数据与使用边界

- 数据保存在本机 `data/`，该目录已被 Git 忽略。运行抓取、发布和 AI 功能时，仍会向 X 和你配置的 LLM 服务发送相应请求与内容。
- 页面没有登录保护，默认只监听 `127.0.0.1`；请勿直接暴露到局域网或公网。
- 官方 API 与 LLM 网关可能产生费用；Cookie 通道仍受 X 的访问和账号限制，项目内预算不是服务商账单。
- 只在有权操作的账号上使用，并保守设置频率。详细操作与参数见[使用指南](docs/guide.md)，产品设计见[设计文档](docs/design.md)。
