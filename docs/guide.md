## 快速开始

Windows 双击 `start.bat`（需先装 `uv`），或命令行：

```bash
uv sync --locked
uv run python -m x_operator.main
```

浏览器打开 http://localhost:8080。首次启动只建空库，**没有任何演示/模拟数据**，也没有「演示模式」——
所有抓取和发送都用你在「设置 → 账号」里填的真实凭据直连 X。旧版本的数据库会自动升级并清掉之前的演示数据（你自己加的账号/素材/规则会保留）。

> **安全提醒**：页面没有登录保护，设置页能看到所有账号的密码 / Cookie / 密钥，所以程序**默认只监听本机**
> （`config/settings.toml` 里 `host = "127.0.0.1"`）。不要改成 `0.0.0.0` 放到局域网/公网上。

起步：① 设置 → 账号 添加账号并「测试连接」；② 要用 AI 时，在设置 → LLM 配置网关和模型；③ 选择素材匹配时添加启用的回复素材，选择 AI 创作时填写创作要求；④ 监控推主 / 搜索规则 添加来源并手动运行。
只有官方 API 账号时，还需到「设置 → 抓取」开启「官方 API 也参与抓取」。
仪表盘的「就绪检查」会直接告诉你还差哪一步。

## 仪表盘与统计

仪表盘的「账号今日发送与额度」按各账号当地日期统计本工具成功发送的主帖与回帖，默认每页 10 个账号，可改为 25 或 50 个，支持账号/显示名搜索、状态与额度筛选、点击表头排序。账号名可跳转该账号的任务队列。
上限与剩余额度每 5 秒重新读取，修改账号日限额后无需重启；养号期显示实际生效上限并附设置原值。调低至已发送量以下时剩余显示 0，历史计数不变。统计不包含在 X 网页或其他工具发送的内容，也不把失败或待发送条目算作成功；已删除账号不列入该表及顶部今日发送汇总。额度尚有剩余仍须满足冷却、活跃时段等发送条件。
搜索、筛选、排序和分页不会被定时刷新重置。最近异常默认收起，展开后显示最近 20 条失败调用，每页 5 条摘要，点「详情」查看完整原始错误。

## 界面语言与版本

左上角品牌旁显示当前程序版本，右上角语言菜单支持 **简体中文 / 繁體中文 / English / 日本語**，首次打开默认「跟随系统（浏览器语言）」。依据浏览器发送的语言偏好及优先级选择支持的语言：英语、日语及各自地区变体使用对应界面，繁体（`zh-Hant`）及台湾、香港、澳门地区使用繁体中文，简体（`zh-Hans`）、中国大陆、新加坡或未指定地区的中文使用简体中文；明确指定的简繁字形优先于地区。没有匹配或未提供语言时回退简体中文。浏览器语言通常跟随系统，但浏览器单独设置的语言优先。

- 手动选择优先于自动识别，按浏览器保存，跨页面及服务重启后继续使用；已有手动选择不会被覆盖。可在菜单切回「跟随系统」，此模式在下次打开或刷新页面时重新识别，不会打断正在编辑的表单。清除浏览器 Cookie 或使用另一浏览器时恢复自动识别。此偏好存于本机 `.nicegui/`，不随代码上传。
- 切换前会提示保存未提交的表单，确认后刷新当前页面，保留当前地址的筛选参数。后台任务继续运行。
- 界面语言只影响导航、表单、按钮、提示及内嵌帮助。素材原文、规则名称、账号备注、搜索语言和 AI 创作语言不会被改写。
- X / LLM 返回的原始错误以及后台任务的原始日志保留原文，便于排查；不对用户内容进行自动翻译。

## 版本维护

版本号统一保存在 `x_operator/version.py`，页面显示与安装包从同一位置读取。采用 `主版本.次版本.补丁`：

| 更新规模 | 示例 | 提交标题 |
|---|---|---|
| 修复、文案、样式及维护 | 0.2.0 → 0.2.1 | `fix:`、`docs:`、`style:`、`chore:` |
| 兼容现有功能的新功能 | 0.2.1 → 0.3.0 | `feat:` |
| 不兼容的数据或使用方式变更 | 0.3.0 → 1.0.0 | `feat!:` 或正文含 `BREAKING CHANGE:` |

本地开发交付前，根据本次更新规模执行（不会触碰业务数据）：

```bash
uv run python scripts/release_version.py --base origin/main --level minor
```

`--level` 可选 `patch`、`minor`、`major`；省略时依据基准之后的提交说明自动判断，未提交改动无法从提交说明识别规模，应显式指定。`--dry-run` 仅预览。
同一批更新相对同一个基准只升版一次，重复执行不会持续加号；已手动提升的版本也会保留。分批交付但尚未推送时，用上一批交付的提交号作为 `--base`。

推送至 GitHub `main` 后，`.github/workflows/version.yml` 会按本次推送中最大的变更级别补上未升版的版本，并提交版本文件。它依据提交语义而非改动行数；使用非规范标题时默认按补丁处理。已在本地升版的提交不会再次加号。
此流程需要仓库启用 Actions 并允许工作流写入代码；若分支保护或并发推送拒绝机器人提交，应查看 Actions 报错，按保护流程提交版本，不强推。拉取该版本提交后重启服务，页面才会显示新版本。

开发完成至少检查启动、相关页面与关键交互，并运行涉及路径的回归检查；涉及共享发送、认证或数据库逻辑时扩大回归范围。界面冒烟使用临时数据和模拟供应商，不能据此声称真实 X 或 LLM 通道已经验证。

## 账号与凭据

入口：设置 → 账号 → 添加 / 编辑。

弹窗里有可展开的**手把手图文步骤**（F12 在哪、点哪个标签、复制哪一列），这里只列要点：

- **官方 API 通道**（主号必须用它）：developer.x.com → App → Settings 里把权限改成 *Read and write* →
  Keys and tokens 生成 API Key / API Key Secret / Access Token / Access Token Secret（Bearer 选填）。
  费用和接口权限以账号的 X 开发者后台为准；程序内的预算与费用估算不等于服务商账单。
- **非官方通道**（仅小号），弹窗里用「方式一 / 方式二」切换按钮**二选一**填（绿框 = Cookie，黄框 = 密码登录，不用两种都填）：
  - 方式一 **Cookie**：Chrome/Edge 登录小号 → F12 → Application（应用）→ Cookies → https://x.com →
    复制 `auth_token`（40 位）和 `ct0`（32 或 160 位）的 **Value** 值。保存时会做格式体检，复制错列会直接提示。
  - 方式二 **用户名 + 密码 + 两步验证 TOTP 密钥**：点击「保存并登录」，通过可选的专用 Chromium 完成网页登录，
    核对登录账号与 handle 一致后保存 Cookie。首次使用会提示下载浏览器，只有点击下载才安装；Cookie 登录不下载浏览器。
    TOTP 填绑定验证器时的完整密钥，不是六位动态验证码。遇到人机验证、邮箱验证码或未知步骤时会暂停自动输入，
    请在弹出的浏览器窗口中手动完成；也可跳过此账号，让下一账号继续。每个账号最多等待 10 分钟。
    窗口打开在**运行服务的电脑**上，需有桌面环境；不使用日常 Chrome 个人资料，每次登录使用隔离会话。
    Cookie 失效后请主动点击账号卡片的「浏览器登录」或重新粘贴 Cookie，后台不会自动弹浏览器。
- **代理**：留空自动使用系统当前代理（Windows 设置里的代理 / HTTP(S)_PROXY 环境变量），填 `direct` 强制直连，
  也可填 `http://127.0.0.1:7890` 指定。「测试连接」成功时会告诉你走的是哪个代理。
- 账号、LLM key、规则、素材正文、模板和抓取记录存在本机 `data/x_operator.db`，附件在 `data/media/`；`data/` 已在 .gitignore。
  浏览器只是显示窗口，换浏览器仍是同一份数据。备份或换电脑时先停止服务，再复制整个 `data/`，并保留自己修改过的 `config/settings.toml`。
  运行抓取、发布和 AI 功能时，会向 X 或配置的 LLM 服务发送相应请求、凭据及所需内容。
- 账号卡片还可设日发帖/回复上限、发送随机间隔、活跃时段与时区——分发器只在活跃时段内、间隔到了才发。
  **主贴和回复各自一套冷却**（`accounts.next_allowed_post_at` / `next_allowed_at`）：发了一条回复不会让主贴等，反之亦然；
  同一账号主贴和回复都到点时先发主贴（定时发帖才能大致准点）。
- **「已订阅 X Premium（会员）」开关**：决定这个账号的推文长度上限（见下面「推文长度」）。请如实勾选。

### 批量导入与浏览器登录任务

设置 → 账号 → **批量导入**，粘贴每行一个账号的列表，先「检查并预览」，再「导入并登录」。
格式为 `用户名,密码,TOTP密钥,邮箱,代理`，前两列必填，后三列可留空；支持 CSV、制表符和 `----` 分隔。
CSV 可带 `username,password,totp_secret,email,proxy` 表头；密码含逗号时用 CSV 双引号包住。
首列必须为账号 handle，每批最多 200 个。格式错误或本批内重复时整批不导入；数据库中已存在的同名账号（含已删除账号）跳过，不覆盖凭据。

导入后的账号先处于待登录状态，成功取得 Cookie 后启用。单账号和批量使用同一登录队列，一次一个浏览器窗口。
在 **登录任务** 查看各账号状态，可跳过当前账号、取消整批或重试未完成账号；关闭面板、切换页面不会中断任务。
如在下载前关闭提示，或服务重启，使用 **批量登录待处理账号** 重新选择尚未完成登录的账号。
登录任务及进度记录仅保留在当前服务进程，重启不会自动重试；已保存的账号和 Cookie 不丢失。

**浏览器组件** 入口可查看安装状态、下载进度和重新下载。组件下载使用系统代理，登录使用各账号配置的代理。
Chromium 安装在数据目录下的 `browser-login/chromium/`；升级项目后如果控制库需要新的浏览器版本，会再次提示下载。
下载耗时受网络影响，超过 20 分钟会停止，可重试。Linux 还需要桌面环境和 Chromium 的系统运行库。
网页登录成功只证明该账号完成了网页登录；请再点 **测试连接** 核对工具的 X 接口连接，接口权限及发帖能力仍以实际请求为准。

## 界面与免责声明

全站使用暖白背景、白色卡片与石墨色正文，紫色只用于当前导航、主要操作和部分标签。标题、筛选工具栏、正文与操作区各自分层，通过留白和细分隔线区分模块。
每页内容底部有「免责声明」文字按钮，点击查看全文，关闭后返回原页面；不会在启动时弹出，也不会遮住日常操作。
输入和选择区域使用白底与清晰边框，说明放在独立浅底区域，长说明可以点击或用键盘展开。任务队列的原推文以引用区展示，「待发布文案」有单独标签，避免与说明混淆。
右下角是可收起的任务进度面板，等待搜索、匹配或 AI 生成时仍可使用其他页面。
文字分三档，一眼能分出「功能」和「说明」：正文 14px 深色是功能内容；时间、计数、@谁这类辅助信息 12px 灰；
怎么用、推荐值这类说明使用可读的中灰色，超过 60 字的说明默认只显示一行（前面带 ? 图标、末尾「更多」），点一下展开全文、再点收起，
输入框下面不再挂一整段话。页顶的功能介绍同样折成一行。

抓取记录、素材库和任务队列中的长原文先展示摘要，可点「展开全文」。失败原因始终显示摘要，点击可查看完整内容；规则的参数、查询语句和创作要求集中在「规则详情」里。

抓取记录卡片保留「自动匹配」「素材库匹配」，「手动选素材」「AI 撰写」「拉黑作者」在「更多操作」中。搜索规则的「重置游标」「删除规则」在卡片的「更多」中，处理逻辑不变。

标签用浅底和文字共同表达含义，图例按需展开，鼠标悬停有解释：

## 一条推文的旅程

```
监控推主 / 搜索规则 → 抓取记录（每条推文：打分、为什么被过滤、状态）
   → 匹配素材 → 任务队列（待审核）→ 人工批准（可改文案）→ 待发送
   → 分发器（活跃时段 / 间隔 / 日上限 / 冷却 / 黑名单 / 去重账本）→ 已发送
```

以下是默认人工审核流程；规则或推主开启免审核、定时计划开启自动批准后，符合条件的内容可直接进入待发送。

各页面：

- **仪表盘**：概况 + 「就绪检查」（没账号/没凭据/没素材会直接标红告诉你）+ 手动运行按钮。
- **任务队列**：逐条看生成说明、改文案、**换素材**、批准/跳过/拉黑；每条标明来源（AI 匹配素材 / 手动选素材 / AI 撰写 / 定时），
  回复类条目还标出目标推文是**哪条搜索规则 / 哪个监控推主**抓来的（搜索「规则名」、推荐流「规则名」、监控 @推主，和抓取记录页同一套写法）；
  各状态按自己的时间倒序（最新在前）：待审核看创建时间，已发送看发送时间，已批准 / 失败 / 已跳过 / 已过期看决定时间；抓取记录按抓取时间倒序；
  「失败」条目可**捞回待审核**：重试清零、失败原因留在条目上（待审核卡片会标红提示），批准后按正常流程重发，时效过了按当前设置重新计时，已回复过的捞不了；
  已发送条目给出 X 上的链接，并**自动回查是否真的存在**（发送接口返回成功 ≠ 一定发出去了；查不到会标红），可手动「重新回查」。
  你正在改文案或开着弹窗时，自动刷新不会把页面冲掉。
  **按发送账号筛选**：顶部状态旁的「发送账号」下拉可以只看某个账号的条目（停用 / 凭据失效的账号也列出来，括号里是当前状态下的条数）；
  状态里多了一项**「未发送的全部（待审核 + 待发送 + 失败）」**，账号失效时一次筛全。选了账号后：
  - **「批量转给其他账号」**：把筛出来的全部条目（不只页面上显示的 200 条）改由选中的启用账号发送，选多个就平均分；
    条目状态不变，待发送的按新账号的活跃时段 / 间隔 / 日上限发，超出新账号长度上限（免费账号 280 单位）的退回待审核；失败的转过去后再点「捞回待审核」；发送中 / 已发送的不动。
  - **「批量删除」**（原「清空此状态」）：只删当前筛选（状态 + 账号）下的条目；「已过期」改为勾选后删除选中项。发送中的条目不能删除；没有其他待处理或已发送任务的抓取记录退回「达标但未生成回复」。
  - 账号凭据失效 / 已暂停时页顶会提示它名下还有多少条发不出去；「设置 → 账号」卡片上有「它的任务（N 条未发送）」按钮直接跳过来。
  **待发送**（已批准）的条目有**「立即发送」**：不等活跃时段和发送间隔，现在就发这一条；账号状态、日上限和合规检查照常，发完间隔照常推进。
  **已跳过**的条目会用中文写明原因（作者冷却期内 / 该推文已回复过 / 作者在黑名单 / 条目已过时效 / 手动跳过），每条有两个按钮：
  **「重新判断」**——按现在的情况把跳过规则全部再查一遍（黑名单、是否已回复过、作者冷却、时效），都不成立就放回待审核，时效不动
  （适合冷却 1 天、时效 3 天这类冷却先到期的情况，或作者已从黑名单移除）。已过时效的移到「已过期」，其他拦截保持跳过；多种原因同时命中时一起展示，过期优先归类。
  筛选到「已跳过」时顶部有「重新判断全部已跳过」，结果分别统计放回待审核、已过期、仍跳过。
  **作者冷却**按所有账号对同一作者最近一次成功回复起算，显示最近回复时间和冷却结束时间；**回复条目时效**从草稿入队起算，保存为固定到期时间。48 小时不是作者冷却期，换账号或等待冷却都不会延长旧草稿的有效期。修改时效设置只影响新生成草稿。
  每分钟的过期清扫覆盖待审核、待发送和已跳过回复；发送中、失败和人工放行条目不参与自动清扫。失败条目继续保留错误，手动捞回时如已过期才按当前设置重算。
  **「强制放回待审核」**——人工放行：不管原因直接放回待审核，条目打上「人工放行」标签，发送时不再按冷却 / 黑名单 / 时效拦，
  也不会自动过期。「该推文已回复过」不能人工放行：去重账本按推文唯一，抓取记录的重新匹配、手动选素材和 AI 撰写也会检查已回复状态，不能借此重复回复。
  **已过期**支持勾选、全选当前列表（最多 200 条，遵循账号筛选）和取消全选：
  - **批量删除**：确认后只删除本次选中的过期任务，不删除素材和发送账本；执行前再次检查状态，已恢复或正在发送的条目不会被删。
  - **批量突破规则**：保留原任务编号、账号、文案和附件，打上「人工放行」标签并放回**待审核**，逐条批准后进入**待发送**，沿用正常时段、间隔和日上限。不会因规则配置了免审核而直接发送。
  - 单条的 **突破规则并放回待审核** 适合先修改文案、附件或账号；**突破规则并发送** 则弹出原文、附件、账号和目标推文，确认后视为批准并立即尝试发送，不等时段和间隔。
  两种突破方式都会绕过作者冷却、黑名单和草稿时效，取消自动过期；同一推文去重、账号状态、日上限、正文长度和附件检查仍保留。同一推文已有其他待审核、待发送、发送中或已发送任务时，不能恢复旧草稿，避免重复排队。
  单条立即发送复用正常分发器的账号锁、记账和回查。账号忙时保留已过期状态；账号停用、日上限或凭据未配置时回到待发送，恢复条件后自动继续；其他错误沿用正常重试或失败处理，失败后仍可捞回待审核。
- **抓取记录**：监控/搜索抓到的所有推文。被过滤的每条都写明**为什么没进队列**，页顶有各状态说明；可按来源、规则、状态筛选。
  **与任务队列的区别**：抓取记录按原推文去重计数；任务队列按发布任务计数，同一原推文重新生成草稿会留下多条历史任务，此外还有无对应抓取记录的定时主帖。两边的总数和过期数不要求一致。
  抓取记录的「回复草稿已过期」表示关联草稿到期且没有其他待审核、待发送、发送中或已发送任务；重新生成后原推文回到「已进任务队列」，但旧草稿仍在任务队列的「已过期」中。原推文本身不会因草稿到期而失效。
  「已进任务队列」也包含发送成功、失败或跳过的任务，不等于「待审核」。卡片优先展示仍在处理的任务，其次已发送任务，并提示历史过期草稿数量；关联链接打开对应状态的任务列表。在队列操作后可点抓取记录页的刷新按钮更新数量。
  支持 URL 直达（`/targets?source=search&rule=3`）。每条可 **「选素材」**（手动从素材库挑一条、可改文案）、
  **「AI 撰写」**（按创作要求现写；写好的创作要求可**存为模板**，下次同类场景直接从模板选——规则/推主里的
  「AI 创作要求」也能用同一批模板）、「自动匹配」（跳过打分和预检，按来源规则的回复方式再生成一次）、删除、拉黑作者。
  这三个按钮**只负责生成草稿进待审核，不代表发得出去**：发送前还会再查一遍黑名单 / 是否已回复过 / 作者冷却 / 条目时效。
  所以被「作者冷却期」拦下来的推文，点了「自动匹配」照样能生成草稿，但发送时会被拦下标「已跳过」，
  而且冷却默认 7 天、条目时效默认 48 小时，多半没等到冷却结束就先过期了。确实要发就在任务队列里用「强制放回待审核」人工放行。
  **「批量自动匹配」**：筛选「已过滤/未达标」或「达标但未生成回复」后，可逐条勾选、全选当前列表或取消全选，再批量处理。
  全选仅覆盖当前显示的最多 150 条，仍遵循来源和规则筛选。提交时固定记录列表与状态；切换页面或筛选不会改变已提交任务。
  各条按自己的来源规则生成，跳过打分和预检，成功后进入待审核；已删除、状态已变或正在匹配的记录跳过，一条出错不阻断后续记录。
  右下角任务面板显示进度，以及入队、未匹配、跳过、出错的汇总和原因；处理期间可以继续操作其他页面。
- **素材库**：增删改、启用/归档、回收站；每条素材可挂**配图 / 视频**（见下面「配图 / 视频」）。
  新建素材时语言默认**「自动判断」**：按正文字符集 + 常用词识别（日/英/简体中文/繁体中文/韩/泰/西/法/德/葡/印尼），弹窗里实时显示识别结果，
  保存时落成具体语言；识别不准或判不出（纯表情 / 链接）时在下拉里手选托底。编辑已有素材默认显示原来存的语言。
  **中文分简体 / 繁体**：按「这/這、们/們、个/個」这类简繁写法不同的常用字各出现几次判断；整段都是两边写法一样的字
  （比如「我在日本工作」）看不出来，先按简体存并提示，要当繁体素材用就手选「繁体中文」。
  旧版本存成「中文」的素材、抓取记录、规则语言，升级时自动按字形分好（规则里的「中文」变成简体 + 繁体都选，行为不变）；
  AI 回复 / 发帖 / 缩写时提示词里会写明「简体中文，全文用简体字」或「繁体中文，全文用繁体字」。
  **「AI 生成素材」**：给主题、风格、语言（含简体 / 繁体中文）、场景、必须包含的 @/链接和条数，预览勾选后入库（标记 AI）。
- **监控推主**：添加后可编辑：**首次回溯小时数**、含不含回复、**观看量区间**、**回复方式**、AI 创作要求。
  观看量区间（下限 / 上限，各自 0 = 不限，可以只填一边，下限大于上限保存会被拦下）：
  - **高于上限**：直接过滤，写明「观看量 X 高于上限」（观看量只会涨，不再看）。
  - **低于下限**：监控通常在推文刚发出时就抓到，那时观看量还低，所以不直接丢——先标「过滤」并打上**复查期**
    （发推时间 + 「下限复查时长」小时，默认 6，最多 48），抓取记录里显示「观看量复查中（至 HH:MM）」；
    复查期内每次监控都会重新看它的观看量，涨过下限就当场走预检和生成回复（运行结果写「N 条复查后观看量达标，已处理」），
    过了复查期还不够才定论「未达下限（已过复查期）」。复查时长填 0 = 不复查，抓到时不够就不要。
  - 开着下限复查时，每次监控对这个推主改为按时间窗拉（复查期，和上次抓到的最新推文之后，取更早的那个），而不是只拉游标之后的；
    已处理过的靠数据库去重，不会重复生成。小号通道本来就是一次请求拉最近的推文，不多花；官方 API 按返回条数计费，会多读一些。
  - 拿不到观看量的推文按 0 算。取消下限后，还在复查中的推文直接定论为过滤。
- **搜索规则**：**推文来源**三选一——关键词搜索 / **某个小号的推荐流（For You）** / 某账号的关注流。推荐流是算法推给那个号的热门内容，
  观看量普遍比搜索高得多，但取决于这个号平时关注谁、点什么赞（先用它关注几十个目标领域账号、刷几天）；只有小号 Cookie 通道能读，
  官方 API 没有推荐流接口（只能读关注流）。推荐流规则不填关键词，靠语义条件 + 观看量门槛筛，按「首次回溯」时间窗、数据库去重，
  跳过转推和回复。之后的打分、预检、回复方式、回复账号轮流全部相同。
  关键词搜索规则：关键词（**逗号隔开 = 命中任意一个**，也可直接写 X 语法）+ 语义条件 + 达标分 + **语言多选**
  （中文分简体 / 繁体两项：官方 API 自动添加语言条件时，两者映射为 `lang:zh`；Cookie 通道不自动附加语言条件，统一在抓回后按推文用字判断简繁再筛，
  不在所选范围的写明「推文语言是 简体中文，不在规则选的语言（繁体中文）内」；太短、看不出简繁的推文两边都放行）+
  **首次回溯小时数** + **观看量区间**（下限 / 上限，各自 0 = 不限，可以只填一边） + **回复方式**；观看量区间在**抓取端**生效：
  - 有下限：改按 X 的「热门」排序（小号通道 Top / 官方 API relevancy，刚发的推文观看量都低，按时间倒序凑不到）在时间窗内找；
  - 只有上限：仍按时间排序、游标照用（热门排序捞出来的恰好是要丢的爆款），用来避开回复会被淹没的大帖；
  - 有任一门槛就一页不够继续翻页，直到凑够「每次抓取条数」或扫到上限（条数 × 10，最多 500，且不超过当日剩余读额度），
    区间外的当场丢掉不入库，拿不到观看量的推文按 0 算；下限大于上限时保存会被拦下；
  - 观看量区间在抓取时筛选，但通过观看量门槛的推文仍可能因语言、预检或语义打分被全部过滤。运行结果里会写扫了多少、低于下限和高于上限各丢了多少、
    这次扫到的观看量范围；若没有结果且能判断是上下限问题，会给出调整提示。扫描上限、X 返回量和时间窗也会影响实际抓取条数；
  **读取附图 / 视频封面一起打分**（默认关）：抓回的推文都会记下附件元信息（图片直链、视频封面和时长，两条通道都不额外计费，
  抓取记录页显示 🖼 / 🎬 标签），打开这个开关才会把它们（低清、每条最多 2 张，视频只能看封面）一起送给打分 AI——
  截图 / 配图能说明作者处境时有用。代价：token 消耗明显增加，且「设置 → LLM」的轻量模型必须支持图片输入（多模态），
  否则打分失败、退回关键词粗估，运行结果里会提示；**「AI 生成规则」**：用大白话描述想找谁，AI 给出关键词、语义条件、语言，检查后保存。
  每个参数旁边都有说明和推荐值。右上「运行所有规则」跑所有启用的规则；每张卡片上「运行此规则」只跑这一条（停用的也能跑）——
  两者都是正式运行：结果进抓取记录、推进游标（没有只看不存的试运行）。右下角任务面板显示第几条规则及抓取/打分/生成阶段，不阻挡其他操作。
  规则卡片显示实际查询：Cookie 通道不自动添加 `lang:`，抓取后本地过滤语言；官方 API 通道保留查询语言条件，再做本地简繁判断。
- **定时发帖计划**（自己账号发帖）：每个计划选账号 + **内容来源** + 时间：
  - 内容来源三选一：**固定一条素材**；**素材池轮流**（按语言/场景标签圈一批启用的发帖素材，每次挑用得最少、最近 30 天没发过的一条）；
    **AI 按主题创作**（不用素材，按主题要求每次现写，可用创作要求模板，必带的 @/链接强制原样出现）。
    AI 主题模式还能挂配图 / 视频：固定几个每次都带，或放一个**附件素材池**每次随机挑 1 个（见下面「配图 / 视频」）。
  - 前两种可开 **AI 改写变体**：每次发前让 AI 在素材基础上换个说法（意思不变、保留链接和 @），并避开最近 30 天发过的内容——
    周期计划必须用素材池或开改写，否则每天发同一段文字会被 X 判重复拒发（固定素材不改写时会在生成说明里提醒）。
  - 节奏：每天固定时间 / 每周固定几天 / **每隔 N 小时或分钟**（如 `6h`、`90m`，从保存时算起，最短 10 分钟）/ 只发一次，按账号时区；「立即生成一次」不等到点。可选「自动批准」跳过人工审核。
  - 生成失败（LLM 出错、素材池空）会在卡片上红字显示原因，下次到点再试；固定素材被删则自动暂停。
    程序没开着错过了到点：错过不到「宽限小时数」照常补发，超过就标「错过」（周期计划跳到下一次）。
- **设置**：账号、自动运行、LLM 网关、合规参数、预算、黑名单（@handle 或数字 id 都能拦）、数据清理、素材附件占用空间统计（列出已无引用可放心删的文件，「前往清理」按钮直接打开 data/media/ 目录）。数字参数保存时会校验范围。
  - **自动运行**页列出所有会自己跑的功能：自动搜索、自动监控（受总开关 + 各自的单独开关，节奏可选**每隔 N 分钟**或
    **每天固定时间点**如 `08:00, 20:00`，按所选时区；改完立即生效）、发送分发（**每隔 N 秒检查一次待发送**，默认 60、可设 10~3600，
    可单独关掉只手动发）、定时发帖计划检查 + 过期清扫（每分钟，始终开）。总开关默认关；表格里显示每项的状态和下次运行时间。
    抓取、匹配、AI 撰写不看账号的活跃时段——不在时段内照样抓、照样生成，条目进任务队列后停在待审核 / 待发送，到了时段内才由分发器发出。
- **免审核**（每条搜索规则 / 每个监控推主各自设，在「回复方式」区，默认关）：这条规则 / 推主自动生成的回复，置信度 ≥ 它自己的阈值
  （默认 0.7）就直接进待发送、不经人工审核，理由里会注明；低于阈值的仍进待审核；发送时的合规检查照常。
  置信度：匹配素材 = AI 对「素材贴不贴这条推文」的信心；AI 按要求创作 = 模型自评「回复切题、可以直接发」的信心（`write_reply` 返回的
  confidence，没给按 0.6）。手动选素材、手动 AI 撰写、「重新匹配」不受影响；定时发帖有自己的「自动批准」。不同场景阈值可以不一样。
- **界面显示时区**（自动运行页顶部，默认东京）：任务队列 / 抓取记录 / 定时发帖等所有页面上的创建、发送、下次运行时间都按它显示，
    页面右上角有「🕒 时区名」提示当前口径。**只影响显示**：账号的活跃时段、每日上限、定时计划到点时间仍按各账号自己的时区判断。

### 回复怎么生成（每条规则 / 每个推主单独选）

抓取记录里的 **自动匹配** 沿用来源规则的回复方式；**素材库匹配** 仅对本次操作改为从已有素材中选择，不修改规则。后者使用启用的「回复」素材，优先同语言、场景相关且使用较少的候选；配置了模型时由模型择优，匹配出错或低置信度时按现有规则选择候选，并在待审核理由里说明。保留素材原文和附件，不调用 AI 撰写、润色或缩写；跨语言选择、超长文案会提示人工检查。回复账号仍按来源规则选择，结果始终进入待审核。

在「达标但未生成回复」或「已过滤 / 未达标」列表中，勾选后可使用 **批量素材库匹配**。两种批量匹配都只处理勾选的记录，保留状态校验和防重复入队逻辑；可以在后台运行期间继续使用其他页面。

这两个状态列表的批量任务可同时运行，进度面板会标明所属列表。同一个状态列表中的「批量自动匹配」和「批量素材库匹配」仍共用防重复启动限制，避免同批记录重复处理。

| 回复方式 | 做什么 | 需要 |
|---|---|---|
| 匹配素材库（默认） | 从启用中的「回复」素材里挑一条（优先同语言；繁体推文没有繁体素材时先退到简体素材并在理由里提醒，反之亦然），**原文使用**（可开「允许轻微润色」，开着时 AI 也会把素材转成推文的简繁字形）。**宽进**：只要有可用素材就尝试给出草稿——AI 择优，AI 拒绝/出错/拿不准时按规则挑用得最少的一条并在理由里说明 | 素材 |
| AI 按要求创作 | 按你写的「创作要求」（主题、立场、必须带的 @/链接、语气）每条现写，必带项缺了会自动重写；**可挂配图 / 视频**（固定几个每条都带，或素材池每条随机挑 1 个） | LLM + 创作要求 |
| 只抓取，手动处理 | 不自动生成，你在抓取记录里逐条「选素材」或「AI 撰写」 | — |

默认进入**待审核**。搜索 / 监控自动生成的回复，可按各自规则的免审核开关与置信度阈值进入**待发送**；从抓取记录手动选素材、AI 撰写、单条或批量自动匹配，仍进入待审核。定时发帖计划使用自己的「自动批准」设置。

### 多账号：谁来回、谁来发

- **主号**：账号弹窗里的「设为主号」开关（只有官方 API 通道能当主号）。主号用来发自己的帖子、以及打开「官方 API 也参与抓取」后作为小号都到上限时的抓取后备；默认**不参与回复**。
- **回复账号**：每条搜索规则 / 每个监控推主可选——
  - 「自动轮流」（默认）：在启用中的非主号里优先挑未达日上限、负载最少的（今天已回 + 待审核/待发送/发送中的回复数），
    多条草稿据此分配；所有候选都到上限时仍可生成草稿，发送受日上限限制。没有可用非主号时才使用后备账号。
  - 「只用指定的账号」：下面的名单里选 1 个 = 固定用它；选多个 = 只在这几个里按上面同样的规则轮流（主号选进来也参与）。
    名单里的账号都被停用 / 删除了会退回自动轮流，理由里写明。
  - 「自动轮流，但排除某些账号」：照常在小号里挑最闲的，名单里的号不参与；小号全被排除时退回主号，
    主号也在名单里就找别的启用账号；启用账号全被排除了就**不生成草稿**（抓取记录里写明原因），绝不动用被排除的号。
  - 规则 / 推主卡片上的标签会写成「回复账号：自动轮流」「@xxx」「轮流：@a、@b」「自动轮流，排除 @c」。
  - 任务队列里每条待审核条目都能临时改「发送账号」。
- **发帖账号**：定时发帖计划新建时选。
- **删除账号**（设置 → 账号卡片上的「删除」）：
  - 还有**没发出去的队列条目**（待审核 / 待发送 / 发送中 / 失败），或有**进行中 / 暂停中的定时发帖计划**用它 → 不让删，
    弹窗写清楚是哪几样、各有几条，并给「去任务队列处理」「去定时发帖」按钮（队列里可按账号筛选后批量转给其他账号或删除）。
  - 处理完之后，**发过东西**的账号（有已发送 / 已跳过 / 已过期记录、发送账本、已结束的计划）做**软删除**：
    凭据清空、状态改暂停，账号列表、仪表盘、回复账号选择、抓取账号池、定时发帖的账号下拉里都不再出现；
    记录原样保留——同一条推文不会被别的号再回、作者冷却照常算，任务队列里显示「@xxx（已删除）」。
    账号页底部会写「另有 N 个已删除的账号」。**以后重新添加同名账号，会接回这条记录**（发送历史和账本连上）。
  - 什么记录都没有的账号直接彻底删除。
  - 两种删除都会把搜索规则 / 监控推主里指向它的设置去掉：回复账号名单里移除（名单空了改回自动轮流）、推荐流账号改回自动。
- 去重账本按推文去重：同一条推文只会被一个账号回。

### 配图 / 视频（附件）

回复和主贴都能带附件。当前上传校验允许图片（jpg/png/webp，单张 ≤5MB）、GIF（≤15MB）、视频（mp4/mov，≤512MB），**合计最多 4 个，支持混合选择**；最终是否被接受仍以发送通道和 X 的实际返回为准。

视频附件在素材库、附件编辑区和任务队列中显示画面缩略图，点击可打开视频预览。已有视频无需重新上传：首次显示时在后台生成，后续读取本地缓存。缩略图保存在 `data/thumbnails/`，不修改原视频；不能解码时显示「预览不可用」，仍可尝试打开原视频。首次安装或更新会自动安装截帧依赖，无需另装 FFmpeg。

上传支持一次选择多个文件。文件传输完成后会逐个保存、查重并加入附件，界面显示已添加数量与上限；超限或保存失败会提示文件名和原因，不会取消同批其他文件。附件仍在上传或保存时不能提交表单，以免保存到不完整的列表。超过 4 个文件应先选择「素材池」模式（总数最多 30 个），等全部附件出现后再保存。

- **在哪加**：素材库「新建 / 编辑素材」（附件跟着素材走：自动匹配、手动选素材、素材池轮流、固定素材都会带上）；
  抓取记录「AI 撰写」弹窗（AI 只写文字，附件原样带上）；
  **搜索规则 / 监控推主选了「AI 按要求创作」时**——弹窗「回复方式」区里的「配图 / 视频怎么带」，
  **固定**（最多 4 个，每条回复都带）或 **素材池**（最多 30 个，每条回复随机挑 1 个，优先挑这条规则 / 推主最近没用过的，有其他可选附件时避免连续使用同一个），
  卡片上显示「📎 N 个附件」；改成别的回复方式再保存会清掉这里的附件设置；
  定时发帖计划「AI 按主题创作」模式——「配图 / 视频怎么带」二选一：
  **固定**（下面放的最多 4 个每次一起发）或 **素材池**（放一批最多 30 个，每次发帖随机挑 1 个，优先挑最近没发过的，有其他可选附件时避免连续使用同一个；
  计划卡片上显示「🎲 附件素材池 N 个」）；
  任务队列每条待审核条目的「附件」按钮（加 / 换 / 去掉，改完再批准）。
- **怎么存**：文件放在 `data/media/`（跟数据库同目录，备份时一起带走），库里只记路径。**内容相同只存一份**：素材库、回复、定时发帖
  共用这个目录，上传时先比大小再比 sha256，和已有附件内容一样就直接复用已有文件（提示「直接复用」），不会重复占空间。上传后的媒体标识有账号与有效期限制，
  所以**发送前才用这条的发送账号上传**，换账号发也没问题。附件文件丢了会标「失败」并写明是哪个文件，不会发出没图的半成品。
- 官方 API 通道走 v1.1 媒体上传（视频 / GIF 分块 + 指定类别等 X 转码完成）；小号通道走 twikit 的 upload_media（等处理完成）。
- 启动时会清掉没有任何记录引用的附件文件（弹窗里传了又删掉的那种）。

### 时间窗

不再有全局的「推文最大年龄」。每条搜索规则、每个监控推主各有一个**首次回溯（小时，默认 24）**，并保存各自的游标：

- 普通关键词搜索（无观看量下限）：首次运行或重置游标后按回溯时间窗抓取；有游标后抓它之后的新内容。只有观看量上限时也沿用游标。
- 关键词搜索有观看量下限：采用热门排序，每轮重新在回溯时间窗里搜索，已入库的靠数据库去重，不是只看游标之后。
- 推荐流 / 关注流：按回溯时间窗筛选并去重，跳过转推和回复；结果取决于所选账号的时间线。
- 监控推主：通常沿用游标；开启观看量下限复查后，会回到复查时间窗重新读取，更新仍在复查期内的记录。

当前程序将官方 API 关键词搜索的回溯上限设为 168 小时（7 天）。监控每次请求最多 100 条，也受读额度和接口实际返回量限制；游标向新内容推进，不保证自动补齐所有更早的历史内容。

### 推文长度（免费账号 280 单位 ≈ 140 个汉字）

程序按「计数单位」检查长度：英文字母/数字/标点每个 1 单位，中日韩文字和 emoji 每个 2 单位，每个链接固定 23 单位
（**没写 http 的裸域名也算链接**，如 `hotube.me`——X 会自动识别，产品同样按 23 计；@handle 和邮箱不算）；
Cookie 小号通道发超过 280 单位的推文会自动按「长推文」发（Premium 账号才发得出去，否则 X 返回错误 186）；
**程序中的免费账号上限为 280 单位**（约 140 个汉字/假名），勾选 Premium 后上限为 25000；实际能否发布长内容仍取决于账号权限与 X 接口。回复和主贴使用同一套程序检查。

- 所有生成内容的出口都过同一道检查：匹配素材、手动选素材、AI 撰写、定时发帖（固定素材 / 素材池 / AI 改写 / AI 主题）。
  发送账号是免费账号且正文超限 → 自动让 AI 缩写（保留链接、@、产品名；两次不达标就原样保留并在说明里标 ⚠）；会员账号不缩写。
- AI 写作类提示里会按发送账号写明上限，尽量一次写在范围内。
- 任务队列每条显示「N/280 单位」（会员显示 /25000），换发送账号时上限随之变；超限时红字提示并出现「AI 缩写」按钮，**超限的条目批不了**。
- 分发器发送前再查一次，超限直接标失败并写明原因，不会把注定被 X 拒绝的请求发出去。

### 发送保护（防重复、防误停）

- 推文发到 X 之后，程序先把「已发出 + X 的推文 id」写死再做其他记账；程序中断时正在发送、结果未知的条目，重启后标为「失败，请到 X 上确认」，**不会自动重发**。
- 发送请求超时/断网时，先到自己的时间线上找一下刚才那条（回复看是不是回的同一条推文），找到就按已发出处理。
- 同一账号只允许一个发送在进行（手动「触发发送」和按设置间隔运行的自动分发不会撞车）。
- 发帖和回复的日限额、发送间隔各自计算。一种类型到达日限额时保留在待发送，另一种类型仍可正常参与调度；两种都满足条件时主帖优先，每轮每账号最多发送一条。日限额按账号时区跨日重新计算，账号停用或不在活跃时段会同时影响两种类型。
- 发送遇到 X 限流（429）不增加重试次数，账号暂停后等待重试；抓取账号池的暂停与续跑按下节的设置执行。
- 非官方通道解析不了 X 的返回时，先探一下登录态：Cookie 好好的就不会被当成「凭据失效」清掉。

### 读额度（设置 → 预算）与费用

- 程序只把**官方 API 通道**的读取计入官方读额度。Cookie / 密码通道的读取单独统计；X 官方 API 和 LLM 服务的实际费用、权限与限制以各自后台为准。
- **抓取账号池**（设置 → 抓取；`core/readpool.py`）：监控 / 搜索处理推主或规则时从池里挑号；推荐流 / 关注流还可以指定读取账号，接口内部翻页不等于每页都重新选号——
  - 小号永远参与：挑「最近 15 分钟请求次数最少」的那个（从 `action_log` 数，429 那次也算），多个小号分摊请求，但仍可能遇到 X 的实际限流；
    每号每 15 分钟的请求上限可设，程序默认 40，不是 X 保证可用的额度。
  - **官方 API 账号默认不参与**（按条计费）：打开「官方 API 也参与抓取」后，小号都到上限、或一个小号都没有时才用它，
    程序内每号每 15 分钟上限默认 5，应按账号实际接口权限调整，读额度熔断照拦。只有官方号、没有小号的用户要打开这个开关。
  - 抓取操作之间随机停 2~6 秒（可设，上限填 0 = 不停），用于控制访问频率。
  - **撞到 429**：该账号暂停「遇到限额后停多少分钟」（默认 15），期间不再被挑；立刻换下一个号重试同一位推主 / 同一条规则，
    这次运行照常跑完。一个号都挑不出来（都暂停 / 都到窗口上限）时监控才停下、记住下次从哪位推主继续，
    到点由调度器自动续跑（不看「自动监控」开关，那是用户已经发起的一次运行）；搜索换不到号时把这条规则留到下次运行。
  - 运行结果会写「本次抓取用了 @a 12 次、@b 11 次」；仪表盘按账号显示当前窗口用量、暂停到几点、以及监控是否有待续跑。
- 程序怎么数：每次抓取按返回条数记进 `action_log.reads_consumed`（开了观看量门槛按扫描条数），发送后回查记 1 条。读额度只统计官方通道；仪表盘另行显示小号通道的读取量。
- 真的会拦：自动轮询在「剩余 ≤ 熔断保留」时停跑，手动运行在当日额度用完时拒绝，每天 0 点（UTC）重置；填 0 = 不限。
- 仪表盘按 $0.005/条估算本月官方读费用——这是程序自己的估算，不是 X 账单，实际单价以开发者后台为准。

## 过滤策略

关键词或时间线抓回的推文，会经过抓取端筛选、入库前检查与回复生成。并不是每一条被 X 返回的推文都会入库：
时间窗外、重复内容，以及搜索抓取端剔除的观看量区间外内容，可能只体现在运行汇总中；进入处理阶段后因语言、预检或相关性不足被过滤的记录，会在「抓取记录」注明原因。
以下是搜索处理流程；监控推主主要按时间窗、观看量和预检处理，不经过搜索规则的语义相关性打分：

1. **抓取与去重**：按时间窗、游标和观看量设置抓取；热门搜索、时间线与监控复查的差异见「时间窗」一节。已入库的推文不重复打分
2. **语言**在规则勾选范围内（留空不限；语言不明放行；中文按用字细分简繁，看不出简繁的放行）
3. **预检**：转推 / 自己的推 / 黑名单 / 已回复过 / 作者冷却期内（默认 7 天）。前三关和已抓过的推文都不花 LLM
4. **相关性打分 ≥ 达标分**（默认 5）。有 LLM：本人明确符合 8~10、沾边拿不准 6~7、新闻/教程/招聘/广告 3~5、无关或看不出意思 0~2。
   无 LLM 或打分调用失败：不足 12 字的有效上下文 2 分；命中新闻/招聘/营销/教程词 3 分；命中抱怨/求推荐/找替代词 8 分；其余有完整上下文的默认 7 分。
5. **生成回复**（按规则的回复方式，见上表）；没生成的标为「达标但未生成回复」，可手动处理

旧库升级时，还停在旧默认值上的达标分（6/7）会自动放宽到 5、素材匹配置信度门槛 0.7 放宽到 0.4；你自己改过的值不动。

## LLM

设置 → LLM 填任意 OpenAI 兼容端点（官方或中转站）的 base_url + api_key 后，相关性打分按你写的语义条件来、素材匹配做语义择优；
不填则用上面说的关键词粗打分，能用但分不出"沾边"和"明确符合"。

**网关与模型**：可以使用已有的 OpenAI 兼容服务；设置 → LLM 也提供 [apimax](https://apimax.io) 入口。
「填入推荐配置」会填入程序预设的模型名（base_url 空着时顺便填入，已填的不覆盖），api_key 使用你自己的。
预设不是可用性保证，模型名与图片输入等能力以实际网关支持情况为准；更换模型后可用「测试连接」检查轻量模型的连接，强模型与具体生成任务仍需分别确认。

### 返回超时：等模型多久

不同模型的生成速度差别很大——快的几秒，推理模型或拥堵的中转站可能要一两分钟。设置 → LLM 里的「返回超时（秒）」就是等多久，
默认 60，允许 10~600。规则：

- 「AI 生成素材」一次要写好几条，按这个值的 **2 倍**等；「测试连接」固定 20 秒。
- 超时按失败处理，**不重试**（该调的是超时或换模型，多等几轮没意义）。报错会写清是哪个任务、哪个模型、等了多少秒，
  并指路「设置 → LLM」调大超时或换更快的模型。例：`AI 按主题创作推文超时：模型 xxx 在 60 秒内没有返回结果…`。
- 连不上网关 / 连接超时 / 网关 4xx、5xx 分开说（key 不对、模型名网关没有、限流、网关挂了），不会都笼统地叫「调用失败」。
- 界面上凡是等 AI 的地方（AI 撰写回复、AI 缩写、AI 生成规则、AI 生成素材、重新匹配、定时发帖「立即生成一次」、测试连接）
  使用右下角任务面板显示状态与耗时，可收起，切换或刷新页面后仍能查看；没有可靠生成百分比时显示等待动画，不把超时比例当作实际进度。
  结束后保留结果和错误信息。AI 生成素材或规则后，点击「查看生成结果」检查、编辑并保存；素材也可稍后再选择入库。
  任务与尚未保存的生成结果只保留在当前服务进程内，重启服务会清除，已写入数据库的内容不受影响。
  后台自动跑的（定时发帖到点生成、自动搜索打分）超时同样只记一次、原因写在计划卡片 / 抓取记录上。

### 哪些任务用轻量模型、哪些用强模型

| 任务 | 模型档 | 为什么 |
|---|---|---|
| 设置页「测试连接」 | 轻量 | 只是通不通 |
| 搜索规则：给每条推文打相关性分 | 轻量 | 量大、判断简单，省钱 |
| 匹配素材库（择优 / 润色） | 强 | 要做取舍，开了润色还要改写 |

| AI 生成素材 | 强 | 要写东西 |

| 定时发帖：AI 按主题创作 | 强 | 要写东西 |
| 超长缩写（免费账号超 280 单位时） | 强 | 要在保住意思和链接/@ 的前提下压缩 |

这张表的唯一来源是代码 `x_operator/llm/client.py` 里的 `SCENE_TIERS`：所有 LLM 调用都按它取模型，**没登记的场景直接报错**，
新增 LLM 功能时需要在那里登记，并同步更新本文。设置 → LLM 页从该登记表显示任务与当前模型名；本指南是静态说明，不会自动随代码更新。

## 常见问题与处理顺序

| 现象 | 优先检查 |
|---|---|
| 模型有返回或扣费，但待发送没有新内容 | 先看右下角任务结果，再看待审核；抓取记录的「达标但未生成回复」和定时计划卡片会说明失败原因。只有满足自动批准条件或人工批准后才进入待发送 |
| X 网页搜得到，工具没有新记录 | 对照实际查询与所用账号，再看回溯时间、游标、观看量、语言与重复记录；Cookie 不自动加语言条件，但抓回后仍筛语言 |
| 批量自动匹配按钮没有出现 | 先筛选「已过滤/未达标」或「达标但未生成回复」；列表有记录时显示选择工具栏，勾选后按钮才可用 |
| AI 生成素材或规则后没看到保存结果 | 在任务面板点击「查看生成结果」；素材勾选入库，规则检查后保存。关闭结果弹窗可稍后再打开，重启服务前应保存 |
| 待发送一直不发 | 查看分发器开关、账号状态、活跃时段、日上限、发送间隔，以及是否被冷却、黑名单、去重、长度或时效检查拦住 |
| 更新后仍是旧界面 | CSS 修改后刷新页面；Python 修改后重启服务，再刷新。确认启动的是更新后的项目目录 |

## 备份与本地更新

停止服务后，备份整个 `data/` 和自己修改过的 `config/settings.toml`。数据库包含凭据和配置，附件在 `data/media/`，两者一起保留；换电脑时安装依赖后放回对应位置。

更新前用 `git status` 检查并保存自己的开发改动，随后在项目目录执行：

```bash
git pull --ff-only
uv sync --locked
uv run python -m x_operator.main
```

有本地冲突或分支分叉时先处理改动，不要强制覆盖。当前服务关闭了 Python 热重载；CSS 文件会在打开页面时重新读取。任务面板记录和未入库的生成结果不会跨服务重启保留。
