# x-operator 使用指南

本文是各功能页面、参数与运行机制的详细说明。快速上手看仓库首页 [README](../README.md)，产品规格看 [design.md](design.md)。

## 快速开始

Windows 双击 `start.bat`（需先装 `uv`），或命令行：

```bash
uv sync
uv run python -m x_operator.main
```

浏览器打开 http://localhost:8080。首次启动只建空库，**没有任何演示/模拟数据**，也没有「演示模式」——
所有抓取和发送都用你在「设置 → 账号」里填的真实凭据直连 X。旧版本的数据库会自动升级并清掉之前的演示数据（你自己加的账号/素材/规则会保留）。

> **安全提醒**：页面没有登录保护，设置页能看到所有账号的密码 / Cookie / 密钥，所以程序**默认只监听本机**
> （`config/settings.toml` 里 `host = "127.0.0.1"`）。不要改成 `0.0.0.0` 放到局域网/公网上。

起步三件事：① 设置 → 账号 添加账号并「测试连接」；② 素材库 加几条「回复」素材；③ 监控推主 / 搜索规则 加来源，然后点「运行一次」。
仪表盘的「就绪检查」会直接告诉你还差哪一步。

## 账号与凭据（设置 → 账号 → 添加 / 编辑）

弹窗里有可展开的**手把手图文步骤**（F12 在哪、点哪个标签、复制哪一列），这里只列要点：

- **官方 API 通道**（主号必须用它）：developer.x.com → App → Settings 里把权限改成 *Read and write* →
  Keys and tokens 生成 API Key / API Key Secret / Access Token / Access Token Secret（Bearer 选填）。
  按量计费：读约 $0.005/条、发 $0.015/条、含链接推文 $0.20/条。
- **非官方通道**（仅小号），弹窗里用「方式一 / 方式二」切换按钮**二选一**填（绿框 = Cookie，黄框 = 密码登录，不用两种都填）：
  - 方式一 **Cookie**：Chrome/Edge 登录小号 → F12 → Application（应用）→ Cookies → https://x.com →
    复制 `auth_token`（40 位）和 `ct0`（32 或 160 位）的 **Value** 值。保存时会做格式体检，复制错列会直接提示。
  - 方式二 **用户名 + 密码 + 两步验证 TOTP 密钥**：程序自己走登录流程（自研，不用 twikit 自带的、会卡在
    键盘输入上的那套），登录成功后自动把 Cookie 存回账号；Cookie 失效时自动重新登录。
    支持：密码、TOTP 两步验证、X 要求补邮箱确认身份（填了「邮箱」就自动过）。
    **不支持邮箱验证码**——遇到会弹出明确提示，先在浏览器登录一次完成验证再试，或改用方式一。
- **代理**：留空自动使用系统当前代理（Windows 设置里的代理 / HTTP(S)_PROXY 环境变量），填 `direct` 强制直连，
  也可填 `http://127.0.0.1:7890` 指定。「测试连接」成功时会告诉你走的是哪个代理。
- 凭据存在本机 `data/x_operator.db`，不会上传；`data/` 已在 .gitignore。
  **所有数据（账号、LLM key、规则、素材、模板、抓取记录）都在这一个文件里**，浏览器只是显示窗口——换 IP、换浏览器打开都是同一份；
  换电脑跑要把 `data/` 一起带走。备份 = 复制这个文件。
- 账号卡片还可设日发帖/回复上限、发送随机间隔、活跃时段与时区——分发器只在活跃时段内、间隔到了才发。
  **主贴和回复各自一套冷却**（`accounts.next_allowed_post_at` / `next_allowed_at`）：发了一条回复不会让主贴等，反之亦然；
  同一账号主贴和回复都到点时先发主贴（定时发帖才能大致准点）。
- **「已订阅 X Premium（会员）」开关**：决定这个账号的推文长度上限（见下面「推文长度」）。请如实勾选。

## 一条推文的旅程

```
监控推主 / 搜索规则 → 抓取记录（每条推文：打分、为什么被过滤、状态）
   → 匹配素材 → 任务队列（待审核）→ 人工批准（可改文案）→ 待发送
   → 分发器（活跃时段 / 间隔 / 日上限 / 冷却 / 黑名单 / 去重账本）→ 已发送
```

各页面：

- **仪表盘**：概况 + 「就绪检查」（没账号/没凭据/没素材会直接标红告诉你）+ 手动运行按钮。
- **任务队列**：逐条看生成说明、改文案、**换素材**、批准/跳过/拉黑；每条标明来源（AI 匹配素材 / 手动选素材 / AI 撰写 / 定时）；
  各状态按自己的时间倒序（最新在前）：待审核看创建时间，已发送看发送时间，已批准 / 失败 / 已跳过 / 已过期看决定时间；抓取记录按抓取时间倒序；
  「失败」条目可**捞回待审核**：重试清零、失败原因留在条目上（待审核卡片会标红提示），批准后按正常流程重发，时效过了按当前设置重新计时，已回复过的捞不了；
  已发送条目给出 X 上的链接，并**自动回查是否真的存在**（发送接口返回成功 ≠ 一定发出去了；查不到会标红），可手动「重新回查」。
  你正在改文案或开着弹窗时，自动刷新不会把页面冲掉。
  **待发送**（已批准）的条目有**「立即发送」**：不等活跃时段和发送间隔，现在就发这一条；账号状态、日上限和合规检查照常，发完间隔照常推进。
  **已跳过**的条目会用中文写明原因（作者冷却期内 / 该推文已回复过 / 作者在黑名单 / 条目已过时效 / 手动跳过），每条有两个按钮：
  **「重新判断」**——按现在的情况把跳过规则全部再查一遍（黑名单、是否已回复过、作者冷却、时效），都不成立就放回待审核，时效不动
  （适合冷却 1 天、时效 3 天这类冷却先到期的情况，或作者已从黑名单移除）；仍不通过的保持跳过并把原因更新成现在的。
  筛选到「已跳过」时顶部有「重新判断全部已跳过」。
  **「强制放回待审核」**——人工放行：不管原因直接放回待审核，条目打上「人工放行」标签，发送时不再按冷却 / 黑名单 / 时效拦，
  也不会自动过期。唯一放不了的是「该推文已回复过」：去重账本按推文唯一，想再回请到抓取记录里重新生成。
- **抓取记录**：监控/搜索抓到的所有推文。被过滤的每条都写明**为什么没进队列**，页顶有各状态说明；可按来源、规则、状态筛选，
  支持 URL 直达（`/targets?source=search&rule=3`）。每条可 **「选素材」**（手动从素材库挑一条、可改文案）、
  **「AI 撰写」**（按创作要求现写；写好的创作要求可**存为模板**，下次同类场景直接从模板选——规则/推主里的
  「AI 创作要求」也能用同一批模板）、「自动匹配」、删除、拉黑作者。
- **素材库**：增删改、启用/归档、回收站；每条素材可挂**配图 / 视频**（见下面「配图 / 视频」）。
  新建素材时语言默认**「自动判断」**：按正文字符集 + 常用词识别（日/英/中/韩/泰/西/法/德/葡/印尼），弹窗里实时显示识别结果，
  保存时落成具体语言；识别不准或判不出（纯表情 / 链接）时在下拉里手选托底。编辑已有素材默认显示原来存的语言。
  **「AI 生成素材」**：给主题、风格、语言、场景、必须包含的 @/链接和条数，预览勾选后入库（标记 AI）。
- **监控推主**：添加后可编辑：**首次回溯小时数**、含不含回复、**回复方式**、AI 创作要求。
- **搜索规则**：**推文来源**三选一——关键词搜索 / **某个小号的推荐流（For You）** / 某账号的关注流。推荐流是算法推给那个号的热门内容，
  观看量普遍比搜索高得多，但取决于这个号平时关注谁、点什么赞（先用它关注几十个目标领域账号、刷几天）；只有小号 Cookie 通道能读，
  官方 API 没有推荐流接口（只能读关注流）。推荐流规则不填关键词，靠语义条件 + 观看量门槛筛，按「首次回溯」时间窗、数据库去重，
  跳过转推和回复。之后的打分、预检、回复方式、回复账号轮流全部相同。
  关键词搜索规则：关键词（**逗号隔开 = 命中任意一个**，也可直接写 X 语法）+ 语义条件 + 达标分 + **语言多选** +
  **首次回溯小时数** + **观看量门槛** + **回复方式**；观看量门槛在**抓取端**生效——改按 X 的「热门」排序
  （小号通道 Top / 官方 API relevancy，刚发的推文观看量都低，按时间倒序凑不到）在时间窗内找，一页不够就继续翻页，直到凑够
  「每次抓取条数」或扫到上限（条数 × 10，最多 500，且不超过当日剩余读额度），低于门槛的当场丢掉不入库，
  不会出现"抓 15 条全被过滤"的情况（官方 API 按扫描条数计费，运行结果里会写扫了多少、丢了多少、最高观看量是多少）；
  **读取附图 / 视频封面一起打分**（默认关）：抓回的推文都会记下附件元信息（图片直链、视频封面和时长，两条通道都不额外计费，
  抓取记录页显示 🖼 / 🎬 标签），打开这个开关才会把它们（低清、每条最多 2 张，视频只能看封面）一起送给打分 AI——
  截图 / 配图能说明作者处境时有用。代价：token 消耗明显增加，且「设置 → LLM」的轻量模型必须支持图片输入（多模态），
  否则打分失败、退回关键词粗估，运行结果里会提示；**「AI 生成规则」**：用大白话描述想找谁，AI 给出关键词、语义条件、语言，检查后保存。
  每个参数旁边都有说明和推荐值。右上「运行所有规则」跑所有启用的规则；每张卡片上「运行此规则」只跑这一条（停用的也能跑）——
  两者都是正式运行：结果进抓取记录、推进游标（没有只看不存的试运行）。运行时弹进度框，实时显示到第几条规则、在抓取/打分/生成哪一步。
- **定时发帖计划**（自己账号发帖）：每个计划选账号 + **内容来源** + 时间：
  - 内容来源三选一：**固定一条素材**；**素材池轮流**（按语言/场景标签圈一批启用的发帖素材，每次挑用得最少、最近 30 天没发过的一条）；
    **AI 按主题创作**（不用素材，按主题要求每次现写，可用创作要求模板，必带的 @/链接强制原样出现）。
    AI 主题模式还能挂配图 / 视频：固定几个每次都带，或放一个**附件素材池**每次随机挑 1 个（见下面「配图 / 视频」）。
  - 前两种可开 **AI 改写变体**：每次发前让 AI 在素材基础上换个说法（意思不变、保留链接和 @），并避开最近 30 天发过的内容——
    周期计划必须用素材池或开改写，否则每天发同一段文字会被 X 判重复拒发（固定素材不改写时会在生成说明里提醒）。
  - 节奏：每天固定时间 / 每周固定几天 / **每隔 N 小时或分钟**（如 `6h`、`90m`，从保存时算起，最短 10 分钟）/ 只发一次，按账号时区；「立即生成一次」不等到点。可选「自动批准」跳过人工审核。
  - 生成失败（LLM 出错、素材池空）会在卡片上红字显示原因，下次到点再试；固定素材被删则自动暂停。
    程序没开着错过了到点：错过不到「宽限小时数」照常补发，超过就标「错过」（周期计划跳到下一次）。
- **设置**：账号、自动运行、LLM 网关、合规参数、预算、黑名单（@handle 或数字 id 都能拦）、数据清理、素材附件占用空间统计（列出已无引用可放心删的文件，「前往清理」按钮直接打开 data/media/ 目录）。数字参数保存时会校验范围。
  - **自动运行**页列出所有会自己跑的功能：自动搜索、自动监控（受总开关 + 各自的单独开关，节奏可选**每隔 N 分钟**或
    **每天固定时间点**如 `08:00, 20:00`，按所选时区；改完立即生效）、发送分发（**每隔 N 秒检查一次待发送**，默认 60、可设 10~3600，
    可单独关掉只手动发）、定时发帖计划检查 + 过期清扫（每分钟，始终开）。总开关默认关；表格里显示每项的状态和下次运行时间。
    抓取、匹配、AI 撰写不看账号的活跃时段——不在时段内照样抓、照样生成，条目进任务队列后停在待审核 / 待发送，到了时段内才由分发器发出。
- **免审核**（每条搜索规则 / 每个监控推主各自设，在「回复方式」区，默认关）：这条规则 / 推主自动生成的回复，置信度 ≥ 它自己的阈值
  （默认 0.7）就直接进待发送、不经人工审核，理由里会注明；低于阈值的仍进待审核；发送时的合规检查照常。
  置信度：匹配素材 = AI 对「素材贴不贴这条推文」的信心；AI 按要求创作 = 模型自评「回复切题、可以直接发」的信心（`write_reply` 返回的
  confidence，没给按 0.6）。手动选素材、手动 AI 撰写、「重新匹配」不受影响；定时发帖有自己的「自动批准」。不同场景阈值可以不一样。
  - **界面显示时区**（自动运行页顶部，默认东京）：任务队列 / 抓取记录 / 定时发帖等所有页面上的创建、发送、下次运行时间都按它显示，
    页面右上角有「🕒 时区名」提示当前口径。**只影响显示**：账号的活跃时段、每日上限、定时计划到点时间仍按各账号自己的时区判断。

### 回复怎么生成（每条规则 / 每个推主单独选）

| 回复方式 | 做什么 | 需要 |
|---|---|---|
| 匹配素材库（默认） | 从启用中的「回复」素材里挑一条（优先同语言），**原文使用**（可开「允许轻微润色」）。**宽进**：只要有素材就一定给一条草稿——AI 择优，AI 拒绝/出错/拿不准时按规则挑用得最少的一条并在理由里说明 | 素材 |
| AI 按要求创作 | 按你写的「创作要求」（主题、立场、必须带的 @/链接、语气）每条现写，必带项缺了会自动重写；**可挂配图 / 视频**（固定几个每条都带，或素材池每条随机挑 1 个） | LLM + 创作要求 |
| 只抓取，手动处理 | 不自动生成，你在抓取记录里逐条「选素材」或「AI 撰写」 | — |

无论哪种，都只生成**待审核**草稿，最后由你批准才发。

### 多账号：谁来回、谁来发

- **主号**：账号弹窗里的「设为主号」开关（只有官方 API 通道能当主号）。主号用来发自己的帖子、以及打开「官方 API 也参与抓取」后作为小号都到上限时的抓取后备；默认**不参与回复**。
- **回复账号**：每条搜索规则 / 每个监控推主可选——
  - 「自动轮流」（默认）：在启用中的小号里挑最闲的（按今天已回 + 队列里待审核/待发送的条数，跳过已到日上限的），
    一轮抓到的多条草稿会均匀分到各小号；一个小号都没有时才退回主号。
  - 指定某个账号：固定用它。
  - 任务队列里每条待审核条目都能临时改「发送账号」。
- **发帖账号**：定时发帖计划新建时选。
- 去重账本按推文去重：同一条推文只会被一个账号回。

### 配图 / 视频（附件）

回复和主贴都能带附件，规则跟 X 一样：图片（jpg/png/webp，单张 ≤5MB）、GIF（≤15MB）、视频（mp4/mov，≤512MB）**合计最多 4 个，可以混搭**（图 + 视频一起发没问题）。

- **在哪加**：素材库「新建 / 编辑素材」（附件跟着素材走：自动匹配、手动选素材、素材池轮流、固定素材都会带上）；
  抓取记录「AI 撰写」弹窗（AI 只写文字，附件原样带上）；
  **搜索规则 / 监控推主选了「AI 按要求创作」时**——弹窗「回复方式」区里的「配图 / 视频怎么带」，
  **固定**（最多 4 个，每条回复都带）或 **素材池**（最多 30 个，每条回复随机挑 1 个，优先挑这条规则 / 推主最近没用过的，不会连着两次用同一个），
  卡片上显示「📎 N 个附件」；改成别的回复方式再保存会清掉这里的附件设置；
  定时发帖计划「AI 按主题创作」模式——「配图 / 视频怎么带」二选一：
  **固定**（下面放的最多 4 个每次一起发）或 **素材池**（放一批最多 30 个，每次发帖随机挑 1 个，优先挑最近没发过的，不会连着两次用同一个；
  计划卡片上显示「🎲 附件素材池 N 个」）；
  任务队列每条待审核条目的「附件」按钮（加 / 换 / 去掉，改完再批准）。
- **怎么存**：文件放在 `data/media/`（跟数据库同目录，备份时一起带走），库里只记路径。**内容相同只存一份**：素材库、回复、定时发帖
  共用这个目录，上传时先比大小再比 sha256，和已有附件内容一样就直接复用已有文件（提示「直接复用」），不会重复占空间。X 的 media_id 只对上传它的账号有效、24 小时内作废，
  所以**发送前才用这条的发送账号上传**，换账号发也没问题。附件文件丢了会标「失败」并写明是哪个文件，不会发出没图的半成品。
- 官方 API 通道走 v1.1 媒体上传（视频 / GIF 分块 + 指定类别等 X 转码完成）；小号通道走 twikit 的 upload_media（等处理完成）。
- 启动时会清掉没有任何记录引用的附件文件（弹窗里传了又删掉的那种）。

### 时间窗

不再有全局的「推文最大年龄」。每条搜索规则、每个监控推主各有一个**首次回溯（小时，默认 24）**：
第一次运行（或重置游标后）只抓这个时间窗内的；之后每次只抓上次游标之后的新内容。
官方 API 的搜索最多只能查最近 7 天（168 小时），填得再大也按 168 抓；监控推主每次最多拉 100 条，更早的下一轮凭游标继续。

### 推文长度（免费账号 280 单位 ≈ 140 个汉字）

X 按「计数单位」算长度：英文字母/数字/标点每个 1 单位，中日韩文字和 emoji 每个 2 单位，每个链接固定 23 单位
（**没写 http 的裸域名也算链接**，如 `hotube.me`——X 会自动识别，产品同样按 23 计；@handle 和邮箱不算）；
Cookie 小号通道发超过 280 单位的推文会自动按「长推文」发（Premium 账号才发得出去，否则 X 返回错误 186）；
**免费账号一条最多 280 单位**（140 个汉字/假名），订阅 Premium 的账号最多 25000。回复和主贴一样。

- 所有生成内容的出口都过同一道检查：匹配素材、手动选素材、AI 撰写、定时发帖（固定素材 / 素材池 / AI 改写 / AI 主题）。
  发送账号是免费账号且正文超限 → 自动让 AI 缩写（保留链接、@、产品名；两次不达标就原样保留并在说明里标 ⚠）；会员账号不缩写。
- AI 写作类提示里会按发送账号写明上限，尽量一次写在范围内。
- 任务队列每条显示「N/280 单位」（会员显示 /25000），换发送账号时上限随之变；超限时红字提示并出现「AI 缩写」按钮，**超限的条目批不了**。
- 分发器发送前再查一次，超限直接标失败并写明原因，不会把注定被 X 拒绝的请求发出去。

### 发送保护（防重复、防误停）

- 推文发到 X 之后，程序先把「已发出 + X 的推文 id」写死再做其他记账；程序中断时正在发送、结果未知的条目，重启后标为「失败，请到 X 上确认」，**不会自动重发**。
- 发送请求超时/断网时，先到自己的时间线上找一下刚才那条（回复看是不是回的同一条推文），找到就按已发出处理。
- 同一账号只允许一个发送在进行（手动「触发发送」和后台每分钟的自动分发不会撞车）。
- X 限流（429）不算重试次数，账号暂停到 X 给的重置时间后自动继续。
- 非官方通道解析不了 X 的返回时，先探一下登录态：Cookie 好好的就不会被当成「凭据失效」清掉。

### 读额度（设置 → 预算）与费用

- **只有官方 API 通道花钱**（X 按返回的推文条数计费，被过滤掉的也算；发一条也计费，含链接的贵得多）。小号 Cookie/密码通道 X 不计费。
- **抓取账号池**（设置 → 抓取；`core/readpool.py`）：监控 / 搜索**每发一次请求前**都从池里挑号——
  - 小号永远参与：挑「最近 15 分钟请求次数最少」的那个（从 `action_log` 数，429 那次也算），多个小号自动分摊、都不撞 X 的窗口限额；
    每号每 15 分钟的请求上限可设（默认 40，X 对 Cookie 通道大约 50）。
  - **官方 API 账号默认不参与**（按条计费）：打开「官方 API 也参与抓取」后，小号都到上限、或一个小号都没有时才用它，
    每号每 15 分钟上限默认 5（Basic 档的推主时间线接口就是 5，Pro 档 900，按套餐填），读额度熔断照拦。只有官方号、没有小号的用户要打开这个开关。
  - 请求之间随机停 2~6 秒（可设，上限填 0 = 不停），像真人刷一样。
  - **撞到 429**：该账号暂停「遇到限额后停多少分钟」（默认 15），期间不再被挑；立刻换下一个号重试同一位推主 / 同一条规则，
    这次运行照常跑完。一个号都挑不出来（都暂停 / 都到窗口上限）时监控才停下、记住下次从哪位推主继续，
    到点由调度器自动续跑（不看「自动监控」开关，那是用户已经发起的一次运行）；搜索换不到号时把这条规则留到下次运行。
  - 运行结果会写「本次抓取用了 @a 12 次、@b 11 次」；仪表盘按账号显示当前窗口用量、暂停到几点、以及监控是否有待续跑。
- 程序怎么数：每次抓取按返回条数记进 `action_log.reads_consumed`（开了观看量门槛按扫描条数），发送后回查记 1 条。读额度只统计官方通道；仪表盘另行显示小号通道的读取量。
- 真的会拦：自动轮询在「剩余 ≤ 熔断保留」时停跑，手动运行在当日额度用完时拒绝，每天 0 点（UTC）重置；填 0 = 不限。
- 仪表盘按 $0.005/条估算本月官方读费用——这是程序自己的估算，不是 X 账单，实际单价以开发者后台为准。

## 过滤策略：默认保留

关键词已经命中的推文，原则上都留给人工审核，只剔除明显没用的。一条推文按顺序过五关（搜索规则页顶部有同样的说明，
并显示当前生效的数值），任何一关没过都会写进「抓取记录」并注明原因：

1. **时间窗**：首次运行只看规则/推主「首次回溯」小时数内的；之后只抓上次游标之后的
2. **语言**在规则勾选范围内（留空不限；语言不明放行）
3. **预检**：转推 / 自己的推 / 黑名单 / 已回复过 / 作者冷却期内（默认 7 天）。前三关和已抓过的推文都不花 LLM
4. **相关性打分 ≥ 达标分**（默认 5）。有 LLM：本人明确符合 8~10、沾边拿不准 6~7、新闻/教程/招聘/广告 3~5、无关或看不出意思 0~2。
   无 LLM：有完整上下文 7、命中新闻/招聘/广告词 3、去掉链接/@/#/表情后不足 12 字 2。
5. **生成回复**（按规则的回复方式，见上表）；没生成的标为「达标但未生成回复」，可手动处理

旧库升级时，还停在旧默认值上的达标分（6/7）会自动放宽到 5、素材匹配置信度门槛 0.7 放宽到 0.4；你自己改过的值不动。

## LLM

设置 → LLM 填任意 OpenAI 兼容端点（官方或中转站）的 base_url + api_key 后，相关性打分按你写的语义条件来、素材匹配做语义择优；
不填则用上面说的关键词粗打分，能用但分不出"沾边"和"明确符合"。

### 哪些任务用轻量模型、哪些用强模型

| 任务 | 模型档 | 为什么 |
|---|---|---|
| 设置页「测试连接」 | 轻量 | 只是通不通 |
| 搜索规则：给每条推文打相关性分 | 轻量 | 量大、判断简单，省钱 |
| 匹配素材库（择优 / 润色） | 强 | 要做取舍，开了润色还要改写 |
| AI 按要求创作回复 | 强 | 要写东西 |
| AI 生成搜索规则 | 强 | 要理解意图、组织关键词 |
| AI 生成素材 | 强 | 要写东西 |
| 定时发帖：AI 改写变体 | 强 | 要换说法还不能丢信息 |
| 定时发帖：AI 按主题创作 | 强 | 要写东西 |
| 超长缩写（免费账号超 280 单位时） | 强 | 要在保住意思和链接/@ 的前提下压缩 |

这张表的唯一来源是代码 `x_operator/llm/client.py` 里的 `SCENE_TIERS`：所有 LLM 调用都按它取模型，**没登记的场景直接报错**，
所以以后加新的 LLM 功能必须先在那里补一行——表不会过期。设置 → LLM 页会把它连同当前填的模型名一起显示出来。
