# 推特(X)自动发推工具 — 需求规格说明书(SPEC)

> 版本:v0.1(2026-07-29 重建稿)
> 背景:服务于 ApiMax 日本市场获客。推特打法已定:①以「公司导入 AI 场景 + 可能遇到的问题 + 解题答案」形式发内容推文;②搜索讨论多模型调用/成本问题的推文,回复介绍服务并邀请试用。本工具把 ① 自动化、给 ② 提供线索队列。

---

## 1. 目标与非目标

### 1.1 目标
- 每天按排程自动发布 1–3 条日语内容推文,长期稳定输出,不依赖人每天手动想选题、写文案。
- 推文由 Claude API 生成,风格统一(面向日本开发者/中小企业 IT 负责人,专业但不硬广)。
- 所有推文默认**先进审核队列,人工点一下确认才发**;跑稳后可按开关切换为全自动。
- 记录发布历史与互动数据(浏览/点赞/回复),便于复盘哪类选题有效。

### 1.2 非目标(v1 不做)
- 不做自动回复/自动私信(X 对 automation 的限制严,误伤封号风险高;互动环节只做「线索发现」,回复仍由人工完成)。
- 不做多账号矩阵、不做买粉/互赞等违反 X 规则的行为。
- 不做图片/视频生成(v1 纯文字推文,可留接口)。

---

## 2. 核心功能

### 2.1 选题库(Topic Pool)
- 一个 YAML/JSON 选题库,按「场景 → 痛点 → ApiMax 解法」三段式组织,例:
  - 场景:社内で ChatGPT と Claude を併用したい
  - 痛点:APIキーが部署ごとにバラバラ、コスト把握できない
  - 解法:APIゲートウェイで一元管理、モデル横断で従量課金
- 初始预填 30–50 条选题(可从 DX 认定企业申請書里的真实场景提炼);工具支持随时增删。
- 每条选题记录使用次数与上次使用时间,生成时优先选「没用过/最久没用」的,避免重复。

### 2.2 推文生成(Claude API)
- 输入:选题 + 系统提示词(定义语气、字数、禁词)。
- 输出:日语推文,≤280 字符(X 按字数计,日文按 2 权重计,需校验);可带 1–2 个话题标签。
- 硬性约束(写进提示词并程序校验):
  - **禁止出现「インボイス対応」「適格請求書」**(公司未取得資格,表述红线);
  - 不出现夸大表述(「最安値」「必ず」等);
  - 品牌名统一为 ApiMax,链接统一用 apimax.io(可加 UTM 参数)。
- 每次生成 2–3 个候选,进审核队列供挑选。

### 2.3 审核队列与发布
- 审核方式(v1 从简):生成的候选写入一个 Markdown/网页审核页,人工标记「批准/拒绝/改写」;被批准的进入待发队列。
- 发布:通过 X API v2 `POST /2/tweets` 发布,OAuth 1.0a User Context(或 OAuth 2.0 PKCE)授权公司账号。
- 排程:cron 驱动,发布时间取日本工作时段(JST 9:00–12:00 / 19:00–22:00 之间随机抖动 ±20 分钟,避免机械感)。
- 失败重试:发布失败(限流/网络)指数退避重试 3 次,仍失败则标记并通知。

### 2.4 互动线索发现(喂给人工)
- 定时搜索关键词(例:`Claude API 料金`、`OpenAI API 高い`、`マルチLLM`、`APIキー 管理`),把命中的推文(作者、内容、链接、时间)写入线索列表。
- 人工每天扫一遍列表,手动回复——工具只负责找,不负责回。
- ⚠️ 依赖 X API 的 search 端点,免费档不提供,详见 §4 成本。

### 2.5 数据记录与复盘
- SQLite 存:选题、生成候选、审核结果、发布记录(tweet id、时间)、互动指标(定时拉取 likes/replies/impressions)。
- 简单周报:每周输出一份 Markdown(发了多少条、哪条互动最好、对应哪个选题类别)。

## 3. 技术方案

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11+ 或 Node 20 | 本机已有 Node 20;Python 生态 tweepy 成熟,二选一 |
| X 接入 | X API v2(tweepy / 官方 SDK) | 发推 + 指标拉取 + 搜索 |
| 文案生成 | Claude API(claude-sonnet-5) | 日语质量要求高,提示词内置红线词校验 |
| 存储 | SQLite 单文件 | 无需部署数据库 |
| 排程 | cron(服务器)或 GitHub Actions schedule | 后者免服务器,但密钥放 GitHub Secrets |
| 审核界面 | v1:静态 HTML + 本地标记 / v2:简单 Web 页 | 从简起步 |
| 配置 | .env(X 密钥、Claude 密钥)+ config.yaml(排程、关键词、开关) | 密钥不进仓库 |

## 4. 成本与前置条件(需确认)

- **X API 付费档**:免费档只有每月 500 条写入、无搜索/指标;要用 §2.4 搜索和 §2.5 指标,需 Basic 档(约 $200/月,以官网当前价格为准)。**v1 可先只做发推(免费档够用),搜索线索功能作为付费后的开关项。**
- X 开发者账号需用公司推特账号申请并通过审核(说明用途为自有账号内容发布,合规)。
- Claude API 费用:每天 3 条 × 3 候选,token 消耗极小,每月 <$1。
- 合规:遵守 X Automation Rules——只发自己账号、不自动回复他人、不重复刷屏。

## 5. 里程碑

1. **M1 骨架(1 天)**:X API 授权跑通,手写一条推文能定时发出;SQLite 记录。
2. **M2 生成线(1–2 天)**:选题库 + Claude 生成 + 红线词校验 + 审核队列(Markdown 版)。
3. **M3 常态运行(1 天)**:cron 排程、失败重试、每周复盘报告;开始每日 1 条试运行 2 周。
4. **M4 可选扩展**:升级 Basic 档后开启互动线索发现、指标拉取;审核 Web 页。

## 6. 待用户确认的问题

1. 部署在哪:本机沙箱不常驻,是放你自己的服务器、VPS,还是用 GitHub Actions 定时跑?
2. X API 是否愿意上 Basic 付费档(决定 §2.4/2.5 能否做)?
3. 发推账号是 ApiMax 官方号还是个人号?
4. 语言只发日语,还是日英混发?
5. v1 用 Python 还是 Node?
